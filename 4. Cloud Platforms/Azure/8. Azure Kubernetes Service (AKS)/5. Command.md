To connect to an Azure AKS (Azure Kubernetes Service) cluster, use:

```bash

# az aks get-credentials --resource-group <RESOURCE_GROUP_NAME> --name <AKS_CLUSTER_NAME>


Example:

# az aks get-credentials --resource-group my-rg --name my-aks-cluster


Verify the connection:

# kubectl get nodes

# kubectl config current-context 

```

If you haven't logged in to Azure yet:

```bash
az login


To switch to a specific subscription:

az account set --subscription "<SUBSCRIPTION_NAME_OR_ID>"

````

Useful commands:

```bash

# List AKS clusters
az aks list -o table

# Show current kubectl context
kubectl config current-context

# List contexts
kubectl config get-contexts


For Azure AD-enabled AKS clusters, you may also need:

kubelogin convert-kubeconfig -l azurecli


Then run:

kubectl get pods -A


to confirm access to the cluster.

```

For storage in Azure AKS, the most commonly used options are:

1. Azure Disk (Block Storage)
Best for databases and single-pod workloads.
High performance.
Can be mounted as ReadWriteOnce (RWO).

Storage Class:

kubectl get storageclass


Example PVC:

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: azure-disk-pvc
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: managed-csi
  resources:
    requests:
      storage: 10Gi

2. Azure Files (Shared Storage)
Shared storage across multiple pods.
Supports ReadWriteMany (RWX).
Good for web applications, shared content, logs.

Example PVC:

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: azure-file-pvc
spec:
  accessModes:
    - ReadWriteMany
  storageClassName: azurefile-csi
  resources:
    requests:
      storage: 10Gi

3. Azure Blob Storage
Object storage.
Best for images, backups, archives, data lakes.
Access via Blob CSI Driver or application SDK.
Check Available Storage Classes
kubectl get sc


Typical output:

managed-csi
managed-csi-premium
azurefile-csi
azurefile-csi-premium

Create Storage Account (CLI)
az storage account create \
  --name mystorageaccount \
  --resource-group myRG \
  --location eastus \
  --sku Standard_LRS

Verify PVC and PV
kubectl get pvc
kubectl get pv

AKS Storage Interview Tip
Azure Disk → High-performance block storage, RWO.
Azure Files → Shared file storage, RWX.
Azure Blob → Object storage for unstructured data.

For DevOps/AKS interviews, remember: Azure Disk = Database workloads, Azure Files = Shared storage, Blob Storage = Images/Backups/Data Lake.

AKS Ingress Controller - Complete Overview

Ingress is a Kubernetes API object that manages external access to services inside the cluster, typically HTTP/HTTPS traffic.

Flow:

Internet
   ↓
Load Balancer
   ↓
Ingress Controller
   ↓
Ingress Resource
   ↓
Service
   ↓
Pod

1. What is an Ingress Controller?

An Ingress resource only defines rules.

An Ingress Controller actually implements those rules.

Without an Ingress Controller, the Ingress YAML does nothing.

Common controllers:

NGINX Ingress Controller
Azure Application Gateway Ingress Controller (AGIC)
Azure Application Gateway for Containers
Traefik
HAProxy
2. NGINX Ingress Controller

Most popular Kubernetes ingress controller.

Installation
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx

helm install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx \
  --create-namespace

Architecture
Internet
   ↓
Azure Load Balancer
   ↓
NGINX Ingress Controller Pod
   ↓
Services
   ↓
Pods

Advantages

✅ Open source

✅ Easy setup

✅ Works on any cloud

✅ SSL termination

✅ URL routing

✅ Host-based routing

3. Azure Application Gateway Ingress Controller (AGIC)

Microsoft-managed solution.

Uses Azure Application Gateway instead of NGINX pods.

Architecture:

Internet
   ↓
Azure Application Gateway
   ↓
AGIC
   ↓
AKS Services
   ↓
Pods


AGIC watches Kubernetes Ingress resources and automatically configures Azure Application Gateway.

Benefits

✅ WAF (Web Application Firewall)

✅ SSL offloading

✅ URL-based routing

✅ Autoscaling

✅ Native Azure Integration

✅ Better enterprise security

NGINX vs AGIC
Feature	NGINX	AGICOpen Source	✅	❌
Runs in AKS Pods	✅	❌
Uses Azure Application Gateway	❌	✅
WAF Support	Basic	✅
Cloud Agnostic	✅	❌
Azure Native	❌	✅
4. ingressClassName

ingressClassName tells Kubernetes which Ingress Controller should handle this ingress.

Example:

spec:
  ingressClassName: nginx


or

spec:
  ingressClassName: azure-application-gateway

Check Ingress Classes
kubectl get ingressclass


Example Output:

NAME                         CONTROLLER
nginx                        k8s.io/ingress-nginx
azure-application-gateway    azure/application-gateway

NGINX Ingress Example
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-app
spec:
  ingressClassName: nginx

  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: my-service
            port:
              number: 80

Azure Application Gateway Example
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: appgw-ingress
spec:
  ingressClassName: azure-application-gateway

  rules:
  - host: app.contoso.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: webapp-service
            port:
              number: 80

Interview One-Liner

Ingress = Kubernetes routing rules.
 Ingress Controller = Component that enforces those rules.
 NGINX Ingress = Kubernetes-hosted ingress controller.
 AGIC = Azure Application Gateway-based ingress controller for AKS.
 ingressClassName = Specifies which ingress controller should process the ingress resource.

 =================================

 Simple answer: Generally production mein dono ek saath use nahi karte. Ek ingress controller choose karte hain.

Most Common Scenario
Option 1: NGINX Ingress Controller

Use when:

Multi-cloud environment (AWS, Azure, GCP)
Cost kam rakhna ho
Development, Test, Staging
Small to Medium production environments
ingressClassName: nginx

Option 2: Azure Application Gateway Ingress Controller (AGIC)

Use when:

AKS Azure mein hi hai
Enterprise environment
WAF (Web Application Firewall) chahiye
Higher security requirements
Azure-native architecture
ingressClassName: azure-application-gateway

Real Production Trend

Small/Medium companies: ✅ NGINX Ingress jyada common

Large enterprises, banks, insurance, healthcare: ✅ Azure Application Gateway + AGIC jyada common

Because:

WAF security
SSL management
Azure integration
Better traffic management
Can Both Be Used?

Yes, technically.

Example:

NGINX Ingress          -> Internal Apps
AGIC                   -> Public Apps


Ingress Classes:

ingressClassName: nginx

ingressClassName: azure-application-gateway


But this adds complexity, so most teams use one primary ingress controller.

Interview Answer (Best)

Q: Which Ingress Controller is mostly used in AKS Production?

Answer:

NGINX Ingress Controller is the most commonly used ingress controller across Kubernetes environments. In Azure enterprise environments, Azure Application Gateway Ingress Controller (AGIC) is preferred when WAF, Azure-native integration, and advanced security features are required.
