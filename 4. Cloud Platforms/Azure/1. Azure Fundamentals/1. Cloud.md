## 1. Azure Fundamentals Overview

Microsoft Azure is a cloud computing platform that provides infrastructure, platforms, databases, networking, storage, security, monitoring, and many other managed services.

Instead of purchasing and maintaining physical infrastructure, organizations can consume Azure resources on demand.

### Basic Cloud Flow

`Users → Internet → Azure → Application → Database / Storage`

### Main Cloud Concepts

| Concept | Meaning |
|---|---|
| IaaS | Infrastructure as a Service |
| PaaS | Platform as a Service |
| SaaS | Software as a Service |
| Public Cloud | Shared cloud infrastructure operated by a cloud provider |
| Private Cloud | Cloud infrastructure dedicated to one organization |
| Hybrid Cloud | Combination of on-premises/private and public cloud |
| Scalability | Ability to increase or decrease capacity |
| Elasticity | Automatic adjustment of resources based on demand |
| High Availability | Keeping applications available despite failures |
| Region | Geographic Azure location containing datacenters |
| Availability Zone | Physically separate datacenter locations within a region |
| Resource Group | Logical container for Azure resources |

---

<a id="2-iaas"></a>

## 2. IaaS

**IaaS = Infrastructure as a Service**

IaaS provides virtualized infrastructure such as:

- Virtual Machines
- Disks
- Virtual Networks
- Load Balancers
- IP addresses
- Network interfaces

Azure manages the physical infrastructure while the customer manages the operating system and applications.

### Responsibility

`Azure → Physical Hardware + Datacenter + Networking`

`Customer → OS + Runtime + Application + Data`

### Azure Examples

- Azure Virtual Machines
- Managed Disks
- Virtual Network
- Load Balancer

### Example

A company needs a Linux server running Nginx.

Instead of purchasing a physical server:

`Azure VM → Ubuntu → Nginx → Application`

### When to Use IaaS

Use IaaS when you need:

- OS-level control
- Custom software installation
- Custom networking
- Legacy applications
- Full server administration

---

<a id="3-paas"></a>

## 3. PaaS

**PaaS = Platform as a Service**

PaaS provides a managed application platform where Azure manages most of the infrastructure and operating system.

The developer mainly focuses on the application and data.

### Responsibility

`Azure → Hardware + Networking + OS + Runtime + Platform`

`Customer → Application + Data`

### Azure Examples

- Azure App Service
- Azure Functions
- Azure SQL Database
- Azure Database for PostgreSQL

### Example

Instead of managing a VM:

`Developer → Code → Azure App Service → Users`

Azure handles infrastructure management, OS patching, and platform maintenance.

### When to Use PaaS

Use PaaS when you want:

- Less infrastructure management
- Faster deployment
- Built-in scaling
- Managed platform
- Easier CI/CD integration

---

<a id="4-saas"></a>

## 4. SaaS

**SaaS = Software as a Service**

SaaS provides a complete software application over the internet.

The customer normally does not manage the infrastructure, operating system, or application platform.

### Responsibility

`Cloud Provider → Infrastructure + Platform + Application`

`Customer → Configuration + Data + Users`

### Examples

- Microsoft 365
- Microsoft Teams
- Salesforce
- ServiceNow

### Example

Instead of installing and maintaining email software:

`User → Microsoft 365 → Email`

### When to Use SaaS

Use SaaS when you need:

- Ready-to-use software
- Minimal infrastructure management
- Fast adoption
- Subscription-based applications

---

<a id="5-iaas-vs-paas-vs-saas"></a>

## 5. IaaS vs PaaS vs SaaS

| Feature | IaaS | PaaS | SaaS |
|---|---|---|---|
| Infrastructure | Customer manages OS/application stack | Azure manages | Azure/provider manages |
| OS | Customer | Azure | Provider |
| Runtime | Customer | Azure | Provider |
| Application | Customer | Customer | Provider |
| Data | Customer | Customer | Customer |
| Control | High | Medium | Low |
| Management | High | Medium | Low |
| Example | Azure VM | App Service | Microsoft 365 |

### Memory

`IaaS → Manage Infrastructure`

`PaaS → Manage Application`

`SaaS → Use Software`

---

<a id="6-public-cloud"></a>

## 6. Public Cloud

A public cloud provides cloud resources through a cloud provider's shared infrastructure.

Examples:

- Microsoft Azure
- AWS
- Google Cloud

Customers share the underlying physical infrastructure, but resources and access are logically isolated.

### Advantages

- No physical datacenter required
- Pay-as-you-go
- Fast provisioning
- Global availability
- Easy scalability

### Example

`Company → Azure → VM / AKS / Storage / Database`

---

<a id="7-private-cloud"></a>

## 7. Private Cloud

A private cloud is dedicated to a single organization.

It can be hosted:

- On-premises
- In a private datacenter
- By a third-party provider

### Advantages

- Greater control
- Custom security requirements
- Dedicated infrastructure
- Compliance support

### Disadvantages

- Higher infrastructure cost
- More administration
- Hardware management
- Scaling can be slower

---

<a id="8-hybrid-cloud"></a>

## 8. Hybrid Cloud

Hybrid cloud combines on-premises/private infrastructure with public cloud.

### Example

A company keeps sensitive systems on-premises but uses Azure for application workloads.

`On-Premises → VPN / ExpressRoute → Azure`

### Production Example

`On-Prem DB → Azure Application → Azure Storage`

### When to Use

- Gradual cloud migration
- Legacy applications
- Regulatory requirements
- Data residency requirements
- Disaster recovery

---

<a id="9-scalability"></a>

## 9. Scalability

**Scalability = Ability to handle increased workload by increasing resources.**

There are two main types.

### Vertical Scaling

Increase the capacity of an existing resource.

`2 CPU / 8 GB RAM → 4 CPU / 16 GB RAM`

Example:

`Azure VM B2s → Larger VM Size`

### Horizontal Scaling

Increase the number of instances.

`1 VM → 3 VMs → 5 VMs`

Example:

`Load Balancer → VM1 + VM2 + VM3`

### Memory

`Vertical = Bigger`

`Horizontal = More`

---

<a id="10-elasticity"></a>

## 10. Elasticity

**Elasticity = Automatically increasing or decreasing resources based on workload.**

Example:

`Low Traffic → 2 Instances`

`High Traffic → 5 Instances`

`Traffic Drops → 2 Instances`

Azure services such as VM Scale Sets and App Service support automatic scaling capabilities.

### Scalability vs Elasticity

| Scalability | Elasticity |
|---|---|
| Ability to increase capacity | Automatic adjustment based on demand |
| Can be manual | Usually automated |
| Planned growth | Dynamic workload changes |
| Example: Add VM capacity | Autoscale based on CPU |

---

<a id="11-high-availability"></a>

## 11. High Availability

**High Availability = Keeping an application available even when some components fail.**

The goal is to minimize downtime.

### Example

Instead of:

`Users → Single VM`

Use:

`Users → Load Balancer → VM1 + VM2`

If VM1 fails, traffic can continue through VM2.

### HA Techniques

- Multiple application instances
- Availability Zones
- Load Balancer
- VM Scale Sets
- Health probes
- Auto-scaling
- Database redundancy
- Backup and disaster recovery

### Important

**High Availability is not the same as Backup.**

`HA → Continue service during failure`

`Backup → Recover data after data loss`

---

<a id="12-azure-regions"></a>

## 12. Azure Regions

An Azure Region is a geographic location containing one or more Azure datacenters.

Examples include:

- Central India
- South India
- West Europe
- East US

### Region Selection Factors

- User location
- Latency
- Data residency
- Compliance
- Service availability
- Cost
- Disaster recovery requirements

### Example

For users in India:

`Users → India Region → Application`

This can reduce network latency compared with deploying only in another continent.

---

<a id="13-availability-zones"></a>

## 13. Availability Zones

Availability Zones are physically separate locations within an Azure region.

Each zone has independent:

- Power
- Cooling
- Networking
- Physical infrastructure

### Architecture

`Azure Region → Zone 1 + Zone 2 + Zone 3`

### Production Example

`Users → Load Balancer → Zone 1 VM + Zone 2 VM + Zone 3 VM`

If one zone becomes unavailable, workloads in other zones can continue serving traffic.

### Region vs Availability Zone

| Region | Availability Zone |
|---|---|
| Geographic Azure location | Isolated location within a region |
| Contains datacenters | Physically separate datacenter location |
| Used for regional deployment | Used for zone-level HA |
| Example: Central India | Zone 1 / Zone 2 / Zone 3 |

### Memory

`Region = Geographic Location`

`Zone = Physical Isolation inside Region`

<a id="14-resource-groups"></a>

## 14. Resource Groups

A Resource Group is a logical container used to organize Azure resources.

Examples of resources:

- VM
- VNet
- Storage Account
- Database
- Load Balancer
- Public IP

### Example

`rg-production`

```text
rg-production
├── VM
├── VNet
├── Load Balancer
├── Storage Account
└── Database
```

### Important Points

- Every Azure resource belongs to a resource group.
- A resource group can contain resources of different Azure services.
- RBAC can be assigned at resource-group scope.
- Policies can apply to resource groups.
- Resource groups help organize and manage resources.
- Deleting a resource group can delete its resources.

### Resource Group Naming

Examples:

```text
rg-dev
rg-test
rg-staging
rg-production
```

<a id="18-production-scenarios"></a>

## 18. Production Scenarios

### Scenario 1 — Application Traffic Increased

**Problem:** Application is receiving significantly more traffic.

**What will you check?**

- CPU
- Memory
- Request rate
- Response time
- Instance count
- Autoscaling configuration

**Solution:**

Use horizontal scaling or autoscaling.

`High Traffic → Autoscale → More Instances`

---

### Scenario 2 — Single VM Failure

**Problem:** Production VM goes down.

**Risk:**

If only one VM exists, the application may become unavailable.

**Solution:**

Deploy multiple instances behind a Load Balancer.

`Users → Load Balancer → VM1 + VM2`

---

### Scenario 3 — Datacenter Failure

**Problem:** One physical location becomes unavailable.

**Solution:**

Use Availability Zones where supported.

`Region → Zone 1 + Zone 2 + Zone 3`

---

### Scenario 4 — Application Needs OS-Level Control

**Problem:** Application requires custom OS configuration.

**Solution:**

Use IaaS such as Azure VM.

---

### Scenario 5 — Application Team Does Not Want to Manage Servers

**Problem:** Developers want to focus only on application deployment.

**Solution:**

Use PaaS such as Azure App Service.

<a id="19-interview-questions"></a>

## 19. Interview Questions

### Q1. What is IaaS?

**Answer:**  
IaaS provides infrastructure such as virtual machines, disks and networking. The cloud provider manages physical infrastructure while the customer manages the operating system, application and data.

---

### Q2. What is PaaS?

**Answer:**  
PaaS provides a managed application platform. Azure manages infrastructure and the operating system, while the customer mainly manages the application and data.

---

### Q3. What is SaaS?

**Answer:**  
SaaS is a complete software application delivered over the internet. The provider manages the infrastructure, platform and application.

---

### Q4. What is the difference between scalability and elasticity?

**Answer:**  
Scalability is the ability to increase or decrease capacity. Elasticity means automatically adjusting capacity according to workload.

---

### Q5. What is High Availability?

**Answer:**  
High Availability means designing systems so that the application remains available even when some infrastructure components fail.

---

### Q6. What is an Azure Region?

**Answer:**  
An Azure Region is a geographic location containing Azure datacenters and services.

---

### Q7. What is an Availability Zone?

**Answer:**  
An Availability Zone is a physically separate location within an Azure region designed to provide isolation from datacenter-level failures.

---

### Q8. Region vs Availability Zone?

**Answer:**

`Region = Geographic Location`

`Availability Zone = Isolated Location Inside a Region`

---

### Q9. What is a Resource Group?

**Answer:**  
A Resource Group is a logical container used to organize and manage related Azure resources.

---

### Q10. Can a Resource Group contain different Azure services?

**Answer:**  
Yes. A Resource Group can contain resources from different Azure services such as VMs, VNets, Storage Accounts and databases.

---

<a id="20-best-practices"></a>

## 20. Best Practices

- Choose the correct service model: IaaS, PaaS or SaaS.
- Use horizontal scaling for highly available applications.
- Use autoscaling for variable workloads.
- Deploy production workloads across Availability Zones where supported.
- Select regions based on latency, compliance and service availability.
- Separate resources using appropriate Resource Groups.
- Use consistent naming conventions.
- Apply RBAC using least privilege.
- Monitor application and infrastructure health.
- Design HA separately from backup and disaster recovery.
