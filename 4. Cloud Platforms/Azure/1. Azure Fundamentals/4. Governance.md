## 1. Azure Governance Overview

Azure Governance is the set of controls used to manage:

- Access
- Compliance
- Resource configuration
- Resource protection
- Cost
- Organizational standards

### Main Governance Services

| Service | Purpose |
|---|---|
| RBAC | Control who can access resources |
| Azure Policy | Control resource configuration and compliance |
| Tags | Identify and organize resources |
| Locks | Prevent accidental deletion or modification |
| Cost Management | Monitor and control Azure spending |

### Governance Flow

`Identity → RBAC → Policy → Tags → Locks → Cost Management`

---

<a id="2-azure-rbac"></a>

## 2. Azure RBAC

**RBAC = Role-Based Access Control**

Azure RBAC controls **who can perform which actions on which Azure resources**.

### RBAC Model

`Security Principal + Role + Scope`

Example:

`Developer + Contributor + Resource Group`

### Security Principals

A security principal can be:

- User
- Group
- Service Principal
- Managed Identity

### Example

A developer needs to restart a VM but should not manage subscriptions.

Assign the appropriate role at the required scope instead of giving Owner access.

### Common Roles

- Owner
- Contributor
- Reader
- User Access Administrator

### Memory

`RBAC = Who can do What at Which Scope`

---

<a id="3-rbac-built-in-roles"></a>

## 3. RBAC Built-in Roles

| Role | Permission |
|---|---|
| Owner | Full access + permission to assign RBAC |
| Contributor | Manage resources but cannot assign RBAC |
| Reader | View resources only |
| User Access Administrator | Manage user access |

### Example

**Developer:**

`Contributor → Resource Group`

**Monitoring Team:**

`Reader → Subscription`

**Security Team:**

Specific security role → Required scope

### Least Privilege

Always provide the minimum permission required.

Avoid:

`Developer → Owner → Subscription`

Prefer:

`Developer → Contributor → Required Resource Group`

---

<a id="4-rbac-scope"></a>

## 4. RBAC Scope

RBAC can be assigned at different scopes.

`Management Group → Subscription → Resource Group → Resource`

### Example

```text id="x0q7m1"
Subscription
│
├── Resource Group A
│   ├── VM
│   └── Storage
│
└── Resource Group B
    └── Database
```

If access is assigned at:

**Subscription:** Applies broadly to resources in that subscription.

**Resource Group:** Applies to resources within that resource group.

**Resource:** Applies only to that resource.

### Best Practice

Use the narrowest practical scope.

`Resource > Resource Group > Subscription > Management Group`

<a id="5-azure-policy"></a>

## 5. Azure Policy

Azure Policy is used to enforce organizational standards and evaluate resource compliance.

### Example Requirements

- Only approved regions
- Required tags
- Approved VM SKUs
- No public IPs
- Encryption must be enabled
- Specific resource types allowed

### Example

Requirement:

> Production resources must have an `Environment` tag.

Azure Policy can audit or enforce this requirement.

### Policy Flow

`Resource Deployment → Azure Policy Evaluation → Compliant / Non-Compliant`

### Important

**RBAC controls access.**

**Policy controls resource configuration/compliance.**

---

<a id="6-azure-policy-effects"></a>

## 6. Azure Policy Effects

Common Azure Policy effects include:

| Effect | Purpose |
|---|---|
| Deny | Block non-compliant deployment |
| Audit | Record non-compliance |
| Modify | Change resource configuration/tags |
| Append | Add required configuration |
| DeployIfNotExists | Deploy required configuration |
| AuditIfNotExists | Audit missing related configuration |
| Disabled | Disable policy |

### Example

**Audit**

`Resource → Missing Tag → Deployment Allowed → Non-Compliant`

**Deny**

`Resource → Missing Required Configuration → Deployment Blocked`

### Production Approach

Start with:

`Audit → Review → Remediate → Deny`

This reduces the risk of unexpectedly breaking existing deployments.

---

<a id="7-azure-policy-vs-rbac"></a>

## 7. Azure Policy vs RBAC

| RBAC | Azure Policy |
|---|---|
| Controls access | Controls compliance |
| Who can do something | What configuration is allowed |
| User/Group/Identity | Resource configuration |
| Role-based | Policy-based |
| Example: Contributor | Example: Allowed Regions |

### Example

A user has Contributor access.

`RBAC → User can create VM`

But the organization allows only Central India.

`Policy → VM in another region is denied`

### Memory

`RBAC = Who`

`Policy = What`

<a id="10-azure-resource-locks"></a>

## 10. Azure Resource Locks

Resource Locks protect Azure resources from accidental deletion or modification.

Locks can be applied to:

- Subscription
- Resource Group
- Individual Resource

### Why Use Locks?

Production resources can be accidentally deleted by:

- Administrator
- Developer
- Automation
- CI/CD pipeline
- Terraform
- Portal operation

A lock provides an additional protection layer.

### Example

`Production Database → CanNotDelete Lock`

---

<a id="11-lock-types-and-scope"></a>

## 11. Lock Types and Scope

Azure provides two important lock types.

### CanNotDelete

Users can modify the resource but cannot delete it.

`Modify = Allowed`

`Delete = Blocked`

### ReadOnly

Users cannot modify or delete the resource.

`Read = Allowed`

`Modify = Blocked`

`Delete = Blocked`

### Comparison

| Lock | Read | Modify | Delete |
|---|---:|---:|---:|
| CanNotDelete | Yes | Yes | No |
| ReadOnly | Yes | No | No |

### Scope

Locks can be applied at:

`Subscription → Resource Group → Resource`

### Production Example

`Production SQL → CanNotDelete`

<a id="13-azure-budgets"></a>

## 13. Azure Budgets

Budgets define expected spending limits and can generate alerts when spending reaches configured thresholds.

### Example

Monthly budget:

`₹100,000`

Alerts:

`50% → Notification`

`80% → Warning`

`100% → Critical Alert`

### Important

A budget is primarily a **monitoring and alerting mechanism**.

Reaching a budget does not automatically mean Azure will stop all resources.

### Production Example

`Budget → 80% → Finance + DevOps Alert`

<a id="14-cost-analysis"></a>

## 14. Cost Analysis

Cost Analysis helps identify where Azure spending is coming from.

### Analyze By

- Subscription
- Resource Group
- Service
- Resource
- Region
- Tags
- Time period

### Example

Unexpected cost increase:

`Cost Analysis → Service → Resource → Usage → Root Cause`

### Production Investigation

If Azure cost suddenly increases:

1. Check Cost Analysis.
2. Identify the service.
3. Identify the resource.
4. Compare usage with previous period.
5. Check recent deployments.
6. Check VM sizes.
7. Check autoscaling.
8. Check storage growth.
9. Check database tier.
10. Optimize the root cause.

<a id="15-cost-optimization"></a>

## 15. Cost Optimization

### Compute

- Right-size VMs
- Stop unused development VMs
- Use autoscaling
- Use reserved capacity where appropriate
- Remove unused resources

### Storage

- Use appropriate access tiers
- Apply lifecycle management
- Delete unnecessary data

### Database

- Select appropriate service tier
- Scale according to workload
- Remove unused databases

### Kubernetes

- Right-size node pools
- Use autoscaling
- Remove unused workloads
- Monitor resource requests and limits

### Cost Optimization Flow

`Measure → Identify → Right-Size → Automate → Monitor`

## 21. Production Governance Architecture

A production Azure environment can use all governance controls together.

### Architecture

`Management Group → Subscriptions → Resource Groups → Resources`

### Access

`Users / Groups / Managed Identities → RBAC → Azure Resources`

### Compliance

`Azure Policy → Allowed Configuration → Resources`

### Organization

`Resources → Tags → Cost / Ownership / Environment`

### Protection

`Production Resources → Resource Locks`

### Cost

`Azure Usage → Cost Management → Budgets → Alerts → Optimization`

### Complete Governance Flow

`Identity → RBAC → Policy → Tags → Locks → Cost Management → Monitoring`

<a id="22-production-scenarios"></a>

## 22. Production Scenarios

### Scenario 1 — Developer Cannot Create VM

**What will you check?**

- RBAC role
- RBAC scope
- Subscription
- Resource Group
- Azure Policy
- Region
- VM SKU
- Quota

**Root Cause Examples:**

- No Contributor permission
- Policy denies VM creation
- Region not allowed
- SKU not allowed
- Subscription quota reached

**Fix:**

Provide the minimum required access or modify the applicable governance configuration after approval.

**Interview Answer:**

"I would first check RBAC and scope, then Azure Policy, subscription, region, SKU and quota to identify whether the issue is permission or governance related."

---

### Scenario 2 — Production Resource Was Deleted

**What will you check?**

- Azure Activity Log
- User/service principal
- Operation
- RBAC permissions
- Resource Lock
- Automation pipeline

**Root Cause:**

A user or automation had sufficient delete permission and the resource was not protected by a deletion lock.

**Fix:**

- Review RBAC
- Apply `CanNotDelete` where appropriate
- Improve change management
- Review automation permissions

---

### Scenario 3 — Azure Bill Increased Suddenly

**What will you check?**

`Cost Analysis → Service → Resource → Usage → Recent Changes`

Check:

- VM size
- Number of instances
- Autoscaling
- Storage growth
- Database tier
- Network usage
- Recent deployments

**Fix:**

Right-size resources, remove unused resources and optimize scaling/storage/database configuration.

---

### Scenario 4 — Required Tags Are Missing

**Problem:** Production resources are created without mandatory tags.

**Solution:**

Use Azure Policy.

`Policy → Required Tags → Compliance`

---

### Scenario 5 — Production Team Needs Read-Only Access

**Requirement:** Team should view resources but not modify them.

**Solution:**

Assign:

`Reader → Resource Group / Subscription`

Use the narrowest appropriate scope.

---

### Scenario 6 — Production Database Must Not Be Deleted

**Solution:**

Apply:

`Azure SQL → CanNotDelete Lock`

Combine this with:

`Least Privilege RBAC + Change Management + Backup`

<a id="23-interview-questions"></a>

## 23. Interview Questions

### Q1. What is Azure RBAC?

**Answer:**  
Azure RBAC controls who can perform which actions on Azure resources at a specific scope.

### Q2. What is the difference between Owner and Contributor?

**Answer:**  
Owner has full resource access including the ability to assign RBAC permissions. Contributor can manage resources but cannot assign Azure RBAC roles.

### Q3. What is Azure Policy?

**Answer:**  
Azure Policy is used to enforce organizational standards and evaluate resource compliance.

### Q4. RBAC vs Azure Policy?

**Answer:**

`RBAC = Who can do what`

`Policy = What configuration is allowed`

### Q5. What are Azure Tags?

**Answer:**  
Tags are key-value metadata used to identify resources and support organization, cost allocation, reporting and automation.

### Q6. Why are Resource Locks used?

**Answer:**  
Resource Locks provide additional protection against accidental deletion or modification of Azure resources.

### Q7. What is the difference between CanNotDelete and ReadOnly?

**Answer:**  
CanNotDelete allows modification but prevents deletion. ReadOnly prevents modification and deletion.

### Q8. What is Azure Cost Management?

**Answer:**  
Azure Cost Management provides tools to analyze spending, create budgets, monitor costs and optimize Azure usage.

### Q9. Does an Azure Budget automatically stop resources?

**Answer:**  
No. A budget primarily provides cost monitoring and alerts. Additional automation is required if resources need to be stopped or changed automatically.

### Q10. How would you enforce mandatory tags?

**Answer:**  
I would use Azure Policy to require or audit mandatory tags and monitor compliance.

### Q11. How would you protect a production database from accidental deletion?

**Answer:**  
I would use least-privilege RBAC, a `CanNotDelete` resource lock, change management and appropriate backup/recovery controls.

### Q12. A user has Contributor access but cannot create a VM. Why?

**Answer:**  
I would check whether an Azure Policy is denying the deployment, whether the user has Contributor access at the correct scope, and whether there are subscription, region, SKU or quota restrictions.

<a id="24-governance-best-practices"></a>

## 24. Governance Best Practices

- Follow least privilege.
- Avoid unnecessary Owner access.
- Assign RBAC at the narrowest practical scope.
- Use Azure Policy for organizational standards.
- Start new policies with Audit before moving to Deny where appropriate.
- Define mandatory tags.
- Standardize tag names and values.
- Protect critical production resources with locks.
- Use Cost Management and budgets.
- Review unexpected cost increases quickly.
- Separate production and non-production environments.
- Regularly review RBAC assignments.
- Monitor policy compliance.
- Combine governance with security and change management.
