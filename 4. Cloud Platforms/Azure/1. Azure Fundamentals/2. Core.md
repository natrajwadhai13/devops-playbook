## 1. Azure Core Overview

Azure provides multiple management layers for organizing and controlling cloud resources.

### Azure Management Hierarchy

`Management Group → Subscription → Resource Group → Resource`

Example:

`Company → Management Group → Production Subscription → Resource Group → VM`

### Main Components

| Component | Purpose |
|---|---|
| Management Group | Organize multiple subscriptions |
| Subscription | Billing and resource boundary |
| Resource Group | Logical container for resources |
| Azure Portal | Web-based management interface |
| Azure CLI | Command-line management |
| Azure PowerShell | PowerShell-based management |
| Azure Resource Manager | Azure deployment and management layer |

---

<a id="2-azure-subscription"></a>

## 2. Azure Subscription

An Azure Subscription is a logical and billing boundary used to manage Azure resources.

Resources are created inside a subscription.

### Example

`Subscription → Resource Groups → Resources`

A subscription can contain:

- Virtual Machines
- Storage Accounts
- VNets
- Databases
- AKS clusters
- App Services

### Why Use Multiple Subscriptions?

Organizations may create separate subscriptions for:

- Production
- Development
- Testing
- Business units
- Different teams
- Cost separation
- Security isolation

### Example

```text
Company
├── Production Subscription
├── Development Subscription
└── Testing Subscription
```

---

<a id="3-subscription-structure"></a>

## 3. Subscription Structure

A subscription provides an important management boundary.

### Common Responsibilities

- Billing
- Resource organization
- Access control
- Quotas and limits
- Policies
- Resource deployment
- Cost tracking

### Example

```text
Production Subscription
├── rg-web-prod
│   ├── VM
│   └── Load Balancer
├── rg-app-prod
│   ├── AKS
│   └── ACR
└── rg-data-prod
    ├── Azure SQL
    └── Storage
```

### Production Strategy

Large organizations often separate environments using subscriptions:

`Production ≠ Development ≠ Testing`

This provides stronger isolation and easier governance.

<a id="4-management-groups"></a>

## 4. Management Groups

Azure Management Groups provide a way to organize multiple Azure subscriptions.

They are useful for enterprise-scale governance.

### Example

```text
Root Management Group
├── Production
│   ├── Production Subscription 1
│   └── Production Subscription 2
├── Non-Production
│   ├── Dev Subscription
│   └── Test Subscription
└── Sandbox
    └── Sandbox Subscription
```

### Why Use Management Groups?

Management Groups help organizations apply governance across multiple subscriptions.

They can be used with:

- Azure Policy
- RBAC
- Governance
- Compliance
- Organization-wide standards

### Example

A company wants all subscriptions to follow a policy requiring specific tags.

Instead of configuring every subscription individually:

`Management Group → Policy → Multiple Subscriptions`

<a id="5-management-group-hierarchy"></a>

## 5. Management Group Hierarchy

Azure supports a hierarchy for organizing resources.

### Hierarchy

`Management Group → Subscription → Resource Group → Resource`

### Example

```text
Management Group
│
├── Production Subscription
│   ├── rg-web
│   │   ├── VM
│   │   └── Load Balancer
│   └── rg-data
│       └── Database
│
└── Development Subscription
    └── rg-dev
        └── VM
```

### Memory

`Management Group = Manage Subscriptions`

`Subscription = Manage Resources + Billing`

`Resource Group = Organize Resources`

`Resource = Actual Azure Service`

<a id="6-azure-portal"></a>

## 6. Azure Portal

Azure Portal is the web-based graphical interface for managing Azure resources.

Portal:

`https://portal.azure.com`

### Common Operations

Using Azure Portal, you can:

- Create resources
- Configure VMs
- Create VNets
- Manage Storage
- Configure RBAC
- View monitoring data
- Manage subscriptions
- View costs
- Configure policies
- Troubleshoot resources

### Example

To create a VM:

`Portal → Virtual Machines → Create → Configure → Review + Create`

### Advantages

- Easy to use
- Visual resource management
- Monitoring dashboards
- Resource configuration
- Useful for troubleshooting
- Good for learning Azure

### Disadvantage

Manual portal operations are difficult to scale and reproduce consistently.

For repeatable deployments, use:

- Azure CLI
- PowerShell
- ARM/Bicep
- Terraform
- CI/CD

<a id="7-azure-cli"></a>

## 7. Azure CLI

Azure CLI is a command-line tool used to manage Azure resources.

### Login

```bash
az login
```

### Check Account

```bash
az account show
```

### List Subscriptions

```bash
az account list --output table
```

### Set Subscription

```bash
az account set --subscription "<subscription-id>"
```

### Create Resource Group

```bash
az group create \
  --name rg-demo \
  --location centralindia
```

### List Resource Groups

```bash
az group list --output table
```

### Show Resource Group

```bash
az group show \
  --name rg-demo
```

### List Resources

```bash
az resource list \
  --resource-group rg-demo \
  --output table
```

### Delete Resource Group

```bash
az group delete \
  --name rg-demo \
  --yes
```

### Why DevOps Engineers Use Azure CLI

Azure CLI is useful for:

- Automation
- CI/CD pipelines
- Scripts
- Infrastructure management
- Troubleshooting
- Repeatable operations

### Production Example

`GitLab CI/CD → Azure CLI → Azure Resources`

<a id="8-azure-powershell"></a>

## 8. Azure PowerShell

Azure PowerShell provides Azure management commands through PowerShell.

The primary module is **Az**.

### Login

```powershell
Connect-AzAccount
```

### Get Current Context

```powershell
Get-AzContext
```

### List Subscriptions

```powershell
Get-AzSubscription
```

### Select Subscription

```powershell
Set-AzContext -SubscriptionId "<subscription-id>"
```

### List Resource Groups

```powershell
Get-AzResourceGroup
```

### Create Resource Group

```powershell
New-AzResourceGroup `
  -Name "rg-demo" `
  -Location "CentralIndia"
```

### List Resources

```powershell
Get-AzResource
```

### Remove Resource Group

```powershell
Remove-AzResourceGroup `
  -Name "rg-demo"
```

### Why Use PowerShell?

PowerShell is useful for:

- Windows administration
- Azure automation
- Enterprise scripts
- Object-based command processing
- CI/CD automation

<a id="9-azure-cli-vs-powershell"></a>

## 9. Azure CLI vs PowerShell

| Feature | Azure CLI | Azure PowerShell |
|---|---|---|
| Interface | Command line | PowerShell |
| Syntax | `az ...` | `Get-Az...`, `New-Az...` |
| Linux | Excellent | Supported |
| Windows | Excellent | Excellent |
| Automation | Excellent | Excellent |
| CI/CD | Very common | Common |
| Output | JSON, table, TSV | PowerShell objects |
| Best for | Cross-platform automation | PowerShell/Windows automation |

### Example

Azure CLI:

```bash
az vm list --output table
```

Azure PowerShell:

```powershell
Get-AzVM
```

### Memory

`Azure CLI → az commands`

`Azure PowerShell → Az cmdlets`

<a id="10-azure-resource-manager"></a>

## 10. Azure Resource Manager

**Azure Resource Manager (ARM)** is the management layer used by Azure to create, update, delete and organize resources.

It provides a consistent management framework for Azure resources.

### Basic Flow

`User / CLI / Portal / PowerShell → Azure Resource Manager → Azure Resource`

### ARM Handles

- Resource deployment
- Resource updates
- Resource deletion
- Access control
- Resource organization
- Resource dependencies
- Tagging
- Locks
- Policies

### Example

When you execute:

```bash
az group create \
  --name rg-demo \
  --location centralindia
```

The request is processed through Azure's management infrastructure.

<a id="11-arm-resource-management"></a>

## 11. ARM Resource Management

ARM provides a consistent control plane for Azure resources.

### Example

You can manage different services using the same management model:

`ARM → VM`

`ARM → Storage`

`ARM → VNet`

`ARM → SQL`

`ARM → AKS`

### Resource IDs

Azure resources have resource IDs.

Example:

```text
/subscriptions/<subscription-id>/resourceGroups/rg-demo/providers/Microsoft.Compute/virtualMachines/my-vm
```

Resource IDs identify the location of a resource within Azure.

### Resource Provider

Azure services use resource providers.

Examples:

```text
Microsoft.Compute
Microsoft.Network
Microsoft.Storage
Microsoft.Sql
Microsoft.ContainerService
```

<a id="12-management-plane-vs-data-plane"></a>

## 12. Management Plane vs Data Plane

Azure operations are commonly understood through two planes.

### Management Plane

Used to manage the Azure resource itself.

Examples:

- Create VM
- Delete VM
- Change VM size
- Create Storage Account
- Configure networking

`User → ARM → Azure Resource`

### Data Plane

Used to access or operate on the data inside the resource.

Examples:

- Read a blob
- Upload a blob
- Query a database
- Read messages from a queue

`Application → Service Endpoint → Data`

### Difference

| Management Plane | Data Plane |
|---|---|
| Manages resource | Uses resource |
| Create/delete/configure | Read/write data |
| ARM | Service-specific endpoint |
| Example: Create Storage Account | Example: Upload Blob |

### Interview Memory

`Management Plane = Manage the Resource`

`Data Plane = Access the Data`

<a id="16-production-scenarios"></a>

## 16. Production Scenarios

### Scenario 1 — Deployment Goes to Wrong Subscription

**Problem:** Pipeline deployed resources into the wrong subscription.

**What will you check?**

- Current Azure context
- Subscription ID
- Service connection
- Pipeline variables
- Azure CLI account

**Commands:**

```bash
az account show
az account list --output table
```

**Root Cause:**

Wrong subscription selected.

**Fix:**

```bash
az account set --subscription "<correct-subscription-id>"
```

**Interview Answer:**

"I would first verify the active Azure subscription and pipeline service connection, then explicitly set the correct subscription before deployment."

---

### Scenario 2 — User Cannot Create a Resource

**What will you check?**

- RBAC role
- Scope
- Subscription
- Resource Group
- Azure Policy
- Quota
- Region availability

**Root Cause:**

The user may not have the required permissions or a policy may be blocking the deployment.

**Fix:**

Assign the minimum required RBAC role at the appropriate scope and verify applicable policies.

---

### Scenario 3 — CLI Command Works for One Subscription but Not Another

**What will you check?**

```bash
az account show
az account list --output table
```

Check:

- Active subscription
- User permissions
- Resource group
- Subscription access

**Root Cause:**

Different subscription context or insufficient permissions.

**Fix:**

```bash
az account set --subscription "<subscription-id>"
```

---

### Scenario 4 — Portal Shows a Resource but CLI Does Not

**What will you check?**

```bash
az account show
az account list --output table
az resource list --output table
```

**Root Cause:**

CLI may be using a different subscription or account context.

**Fix:**

Select the correct subscription and verify permissions.

---

### Scenario 5 — Production Resources Must Be Centrally Governed

**Solution:**

Use Management Groups with centralized governance.

`Management Group → Policy / RBAC → Multiple Subscriptions`

### Q1. What is an Azure Subscription?

**Answer:**  
An Azure Subscription is a management and billing boundary in Azure. Azure resources are deployed inside subscriptions.

### Q2. Why do organizations use multiple subscriptions?

**Answer:**  
To separate environments, teams, billing, security boundaries and governance requirements.

**Answer:**  
A Management Group is used to organize multiple Azure subscriptions and apply governance consistently across them.

**Answer:**

`Management Group → Subscription → Resource Group → Resource`

### Q5. What is Azure Portal?

**Answer:**  
Azure Portal is the web-based graphical interface used to create, configure, monitor and troubleshoot Azure resources.

**Answer:**

**Answer:**

<a id="18-best-practices"></a>

## 18. Best Practices

- Use separate subscriptions when strong environment or organizational isolation is required.
- Use Management Groups for enterprise governance.
- Use Resource Groups to organize related resources.
- Verify the active subscription before production changes.
- Use RBAC with least privilege.
- Prefer automation over repeated manual Portal changes.
- Use Azure CLI or PowerShell in CI/CD automation.
- Use Infrastructure as Code such as Terraform or Bicep for repeatable deployments.
- Use Azure Activity Log to audit management operations.
- Apply consistent naming and tagging standards.
- Avoid making uncontrolled production changes directly through the Portal.
