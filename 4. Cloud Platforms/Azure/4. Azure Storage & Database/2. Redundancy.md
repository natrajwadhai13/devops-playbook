## Azure Storage Redundancy

Azure Storage redundancy determines **how many copies of your data are maintained and where those copies are stored**. It protects data from disk, hardware, datacenter, zone, and regional failures.

| Type | Full Form | Copies / Location | Protects Against | Typical Use |
|---|---|---|---|---|
| **LRS** | Locally Redundant Storage | 3 copies in one datacenter | Hardware/disk failure | Dev/Test, low-cost workloads |
| **ZRS** | Zone-Redundant Storage | 3 copies across availability zones | Datacenter/zone failure | Production workloads in one region |
| **GRS** | Geo-Redundant Storage | LRS in primary + replicated copy in secondary region | Regional disaster | DR / business continuity |
| **GZRS** | Geo-Zone-Redundant Storage | ZRS in primary + geo-replication to secondary region | Zone + regional failure | Critical production workloads |

### 1. LRS — Locally Redundant Storage

```text
Primary Region
└── Datacenter
    ├── Copy 1
    ├── Copy 2
    └── Copy 3
```

- Maintains multiple copies within a **single datacenter**.
- Lowest-cost redundancy option.
- Protects against individual hardware/disk failures.
- Does **not** protect against a complete datacenter or regional failure.

**Use:** Development, testing, temporary data, workloads where regional DR is not required.

---

### 2. ZRS — Zone-Redundant Storage

```text
Primary Region
├── Availability Zone 1 → Copy
├── Availability Zone 2 → Copy
└── Availability Zone 3 → Copy
```

- Replicates data synchronously across availability zones in the same region.
- Protects against failure of an entire availability zone.
- Data remains within the same Azure region.

**Use:** Production applications requiring high availability without cross-region replication.

---

### 3. GRS — Geo-Redundant Storage

```text
Primary Region                    Secondary Region
┌─────────────────┐               ┌─────────────────┐
│ LRS             │ ── Async ──→ │ LRS             │
│ Copy 1/2/3      │               │ Copy 1/2/3      │
└─────────────────┘               └─────────────────┘
```

- Stores data redundantly in the **primary region**.
- Asynchronously replicates data to a **secondary Azure region**.
- Protects against a complete regional disaster.
- Secondary copy is normally not directly available for normal read operations unless using the appropriate read-access configuration.

**Use:** Disaster recovery and business continuity.

---

### 4. GZRS — Geo-Zone-Redundant Storage

```text
Primary Region                         Secondary Region
┌─────────────────────────┐            ┌─────────────────┐
│ Zone 1 → Copy           │            │                 │
│ Zone 2 → Copy           │ ────────→ │ Geo Copy        │
│ Zone 3 → Copy           │            │                 │
└─────────────────────────┘            └─────────────────┘
```

- Combines **ZRS + GRS**.
- Data is redundantly stored across availability zones in the primary region.
- Data is also asynchronously replicated to a secondary region.
- Provides protection against both:
  - Availability-zone failure
  - Regional disaster

**Use:** Mission-critical production applications.

---

## Quick Comparison

```text
LRS  → Multiple copies → One datacenter
ZRS  → Multiple copies → Multiple zones → Same region
GRS  → Primary region + Secondary region
GZRS → Multiple zones + Secondary region
```

### Interview Memory Trick

**LRS = Local**

**ZRS = Zone**

**GRS = Geo**

**GZRS = Geo + Zone**

### Production Selection

```text
Dev/Test                  → LRS
Production HA             → ZRS
Production + DR           → GRS
Critical Production + DR  → GZRS
```

**Important:** Redundancy is not the same as backup. **GRS/GZRS replication does not replace a proper backup strategy**, especially when protection against accidental deletion, corruption, or unwanted changes is required.
