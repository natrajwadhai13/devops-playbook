<a id="vm-fundamentals"></a>

## 1. Azure VM Fundamentals

Azure Virtual Machine is an **IaaS compute service** that provides a virtual server in Azure.

With Azure VM, Azure manages the underlying physical infrastructure, while you manage the operating system, software, application, configuration and security inside the VM.

**Flow:** `Azure Infrastructure → VM → OS → Runtime → Application`

### Azure vs Customer Responsibility

| Azure manages                   | Customer manages       |
| ------------------------------- | ---------------------- |
| Physical datacenter             | Operating system       |
| Physical servers                | Users and permissions  |
| Hypervisor                      | Installed software     |
| Physical networking             | Application            |
| Physical storage infrastructure | OS configuration       |
| Azure platform                  | Patching and hardening |

### Common VM Use Cases

- Linux/Windows application servers
- Web servers
- Database servers
- Development/test environments
- Legacy applications
- Build agents
- Custom software requiring OS-level access
- Batch workloads

<a id="vm-types"></a>

## 2. Azure VM Types

Azure provides different VM families optimized for different workloads.

| VM Category       | Examples    | Main Purpose               | Typical Use                                     |
| ----------------- | ----------- | -------------------------- | ----------------------------------------------- |
| General Purpose   | B, D series | Balanced CPU + RAM         | Web/app servers, dev/test                       |
| Compute Optimized | F series    | Higher CPU ratio           | CPU-intensive workloads                         |
| Memory Optimized  | E, M series | High RAM                   | Databases, in-memory workloads                  |
| Storage Optimized | L series    | High disk IOPS/throughput  | Data processing, storage-heavy apps             |
| GPU Optimized     | NC, ND, NV  | GPU compute                | AI/ML, graphics, visualization                  |
| HPC               | (H)         | Supercomputing simulations | High-performance computing/scientific workloads |

### VM Selection

`Workload → CPU → RAM → Disk IOPS → Disk Throughput → Network → Region → Cost → VM SKU`

### Interview Point

Do not select a VM only based on CPU.

Consider:

**CPU + Memory + Disk IOPS + Disk Throughput + Network + Availability + Cost**

<a id="vm-images"></a>

## 3. VM Images

A VM image is a template used to create a VM.

| Image Type            | Description                  | Example Use                   |
| --------------------- | ---------------------------- | ----------------------------- |
| Marketplace Image     | Ready-made Azure image       | Ubuntu, Windows, RHEL         |
| Custom Image          | Organization-specific image  | Standardized server           |
| Azure Compute Gallery | Centralized image management | Enterprise image distribution |

### Common Operating System Images

- Ubuntu
- Windows Server
- Red Hat Enterprise Linux
- SUSE Linux Enterprise
- Other Azure Marketplace images

### Marketplace Image

Example:

```bash
az vm image list \
  --location eastus \
  --publisher Canonical \
  --offer ubuntu-24_04-lts \
  --all \
  --output table
```

### Custom Image

A custom image can contain:

- Base OS
- Security configuration
- Required packages
- Monitoring agent
- Application dependencies
- Standard configuration

**Flow:** `Base OS → Configure → Harden → Generalize → Image → VM`

### Azure Compute Gallery

Used to manage and distribute standardized VM images across environments, subscriptions and regions.

**Production Benefit:** Consistent configuration, faster provisioning, repeatable deployments and better compliance.

<a id="vm-sizes"></a>

## 4. VM Sizes

VM size determines the compute resources available to the VM.

| Resource             | Controlled by VM Size |
| -------------------- | --------------------- |
| vCPU                 | Yes                   |
| Memory               | Yes                   |
| Network capacity     | Yes                   |
| Maximum data disks   | Yes                   |
| Disk IOPS capability | Depends on SKU        |
| Disk throughput      | Depends on SKU        |
| Temporary storage    | Depends on SKU        |

Example:

```text
Standard_D4s_v5
```

The exact CPU, memory, disk and network limits depend on the selected SKU.

### Check VM Sizes

```bash
az vm list-sizes \
  --location eastus \
  --output table
```

### Resize VM

```bash
az vm resize \
  --resource-group my-rg \
  --name my-vm \
  --size Standard_D4s_v5
```

### Scaling

| Scaling            | Meaning               | Example            |
| ------------------ | --------------------- | ------------------ |
| Vertical Scaling   | Increase VM resources | D2 → D4 → D8       |
| Horizontal Scaling | Increase VM instances | 1 VM → 2 VM → 4 VM |

**Important:** Horizontal scaling is generally handled through services such as VM Scale Sets, which will be covered separately.

<a id="vm-disks"></a>

## 5. Azure VM Disks

Azure VM storage can be categorized as follows:

| Disk           | Purpose                       | Persistent? |
| -------------- | ----------------------------- | ----------- |
| OS Disk        | Operating system              | Yes         |
| Data Disk      | Application/data storage      | Yes         |
| Temporary Disk | Temporary/local workload data | No          |

### OS Disk

Contains the operating system.

Examples:

- Ubuntu
- RHEL
- Windows Server

### Data Disk

Used for:

- Application data
- Database files
- Logs
- Persistent application storage

### Temporary Disk

Used for temporary data.

**Important:** Do not store critical persistent data on the temporary disk because data may be lost during certain VM operations.

<a id="ssh-rdp"></a>

## 7. SSH and RDP

| Access | OS      | Default Port | Typical Authentication                 |
| ------ | ------- | -----------: | -------------------------------------- |
| SSH    | Linux   |       TCP 22 | SSH key/password                       |
| RDP    | Windows |     TCP 3389 | Windows credentials/Entra-based access |

### Linux SSH

```bash
ssh username@<PUBLIC-IP>
```

Using private key:

```bash
ssh -i mykey.pem username@<PUBLIC-IP>
```

### Windows RDP

```text
mstsc
```

PowerShell connectivity test:

```powershell
Test-NetConnection <VM-IP> -Port 3389
```

### Secure Access

Avoid exposing SSH/RDP to the entire internet.

Bad:

```text
0.0.0.0/0
```

Preferred:

`Administrator → Bastion/VPN/Private Network → VM`

### SSH Troubleshooting

`Client → DNS/IP → NSG → Route → NIC → OS Firewall → SSH Service → Authentication`

```bash
systemctl status ssh
ss -lntp | grep :22
```

Ubuntu firewall:

```bash
sudo ufw status
```

### RDP Troubleshooting

`Client → IP → NSG → Route → Windows Firewall → RDP Service → Authentication`

<a id="vm-extensions"></a>

## 8. VM Extensions

VM Extensions are Azure components used to perform post-deployment configuration or install software/agents inside a VM.

| Extension / Capability | Purpose                                    |
| ---------------------- | ------------------------------------------ |
| Custom Script          | Execute installation/configuration scripts |
| Azure Monitor Agent    | Collect monitoring data                    |
| Antimalware            | Security protection                        |
| DSC Extension          | Configuration management                   |
| Key Vault Extension    | Certificate/secret-related integration     |
| Dependency Agent       | Dependency/monitoring scenarios            |

VM Extensions work through the **Azure VM Agent**.

**Flow:** `VM Created → VM Agent → Extension → Configuration → Application Ready`

List extensions:

```bash
az vm extension list \
  --resource-group my-rg \
  --vm-name my-vm \
  --output table
```

<a id="custom-script"></a>

## 9. Custom Script Extension

Custom Script Extension allows scripts to run inside an Azure VM.

### Linux Example

```bash
az vm extension set \
  --resource-group my-rg \
  --vm-name my-vm \
  --name customScript \
  --publisher Microsoft.Azure.Extensions \
  --version 2.1 \
  --settings '{"fileUris":["https://example.com/install.sh"],"commandToExecute":"bash install.sh"}'
```

### Windows Example

```powershell
az vm extension set `
  --resource-group my-rg `
  --vm-name my-vm `
  --name CustomScriptExtension `
  --publisher Microsoft.Compute `
  --version 1.10 `
  --settings '{"commandToExecute":"powershell -ExecutionPolicy Unrestricted -File install.ps1"}'
```

### Simple Linux Script

```bash
#!/bin/bash

apt-get update
apt-get install -y nginx
systemctl enable nginx
systemctl start nginx
```

### Production Usage

`VM Provisioning → Custom Script → Install Packages → Configure → Start Service → Verify`

### When to Use

Good for:

- Initial VM bootstrap
- Installing agents
- Installing packages
- Small configuration tasks
- Post-deployment automation

For large configuration requirements, prefer:

- Infrastructure as Code
- Configuration Management
- Golden Images
- CI/CD
- Azure Automation

<a id="managed-disks"></a>

## 10. Managed Disks

Azure Managed Disks are Azure-managed block storage volumes for VMs.

Azure handles the underlying storage management, so administrators do not need to manually manage storage accounts for individual VM disks.

### Benefits

- Simplified management
- High availability options
- Scalable storage
- Disk snapshots
- Backup integration
- Encryption
- Integration with Azure VMs

### Create Data Disk

```bash
az disk create \
  --resource-group my-rg \
  --name my-data-disk \
  --size-gb 128 \
  --sku Premium_LRS
```

Attach:

```bash
az vm disk attach \
  --resource-group my-rg \
  --vm-name my-vm \
  --name my-data-disk
```

Check VM:

```bash
az vm show \
  --resource-group my-rg \
  --name my-vm \
  --show-details
```

<a id="disk-management-linux"></a>

## 11. Linux Data Disk Configuration

After attaching a disk:

```bash
lsblk
sudo fdisk -l
```

Create partition:

```bash
sudo fdisk /dev/sdc
```

Format:

```bash
sudo mkfs.ext4 /dev/sdc1
```

Create mount point:

```bash
sudo mkdir /data
```

Mount:

```bash
sudo mount /dev/sdc1 /data
```

Verify:

```bash
df -h
```

### Persistent Mount

Get UUID:

```bash
sudo blkid
```

Add UUID to:

```text
/etc/fstab
```

Test:

```bash
sudo mount -a
```

**Flow:** `Attach Disk → Partition → Format → Mount → fstab → Verify`

<a id="vm-security"></a>

## 12. VM Security

### Network Security

`Internet → NSG → VM NIC/Subnet → Application`

Allow only required ports.

| Service | Port | Recommendation                 |
| ------- | ---: | ------------------------------ |
| SSH     |   22 | Restrict source                |
| HTTP    |   80 | Only when required             |
| HTTPS   |  443 | Preferred web traffic          |
| RDP     | 3389 | Restrict source/private access |

### Identity & Access

Prefer:

- Microsoft Entra ID
- Managed Identity
- Azure RBAC
- SSH keys
- Least privilege

Avoid:

- Hardcoded passwords
- Hardcoded secrets
- Public SSH/RDP access
- Excessive permissions

### OS Security

- Regular patching
- Disable unused services
- Restrict inbound ports
- Enable Defender for Cloud where appropriate
- Use disk encryption
- Enable monitoring
- Follow least privilege

<a id="vm-troubleshooting"></a>

## 14. VM Troubleshooting

### Standard Method

`Alert → Scope → VM Status → Network → OS → Service → Logs → Metrics → Root Cause → Fix → Verify`

### VM Not Reachable

Check:

1. VM running state
2. Public/private IP
3. NSG
4. Route
5. NIC
6. OS firewall
7. Application/service
8. Logs

### CPU High

```bash
top
htop
ps aux --sort=-%cpu | head
```

Azure:

`VM → Monitoring → Metrics → CPU Percentage`

### Memory High

```bash
free -h
top
ps aux --sort=-%mem | head
```

### Disk Full

```bash
df -h
du -sh /*
```

Check large files/directories and clean unnecessary data or expand storage.

### SSH Failure

```bash
systemctl status ssh
ss -lntp | grep :22
```

Then:

`Client → NSG → Route → NIC → OS Firewall → SSH Service → Authentication`

### VM Extension Failure

```bash
az vm extension list \
  --resource-group my-rg \
  --vm-name my-vm \
  --output json
```

Check extension status, VM Agent health and extension logs.

<a id="vm-hands-on"></a>

## 16. Hands-on: Create Linux VM

Login:

```bash
az login
```

Create resource group:

```bash
az group create \
  --name my-rg \
  --location eastus
```

Create VM:

```bash
az vm create \
  --resource-group my-rg \
  --name my-linux-vm \
  --image Ubuntu2404 \
  --size Standard_D2s_v5 \
  --admin-username azureuser \
  --generate-ssh-keys
```

Open HTTP:

```bash
az vm open-port \
  --resource-group my-rg \
  --name my-linux-vm \
  --port 80
```

Get public IP:

```bash
az vm show \
  --resource-group my-rg \
  --name my-linux-vm \
  --show-details \
  --query publicIps \
  --output tsv
```

SSH:

```bash
ssh azureuser@<PUBLIC-IP>
```

Install Nginx:

```bash
sudo apt update
sudo apt install nginx -y
sudo systemctl enable nginx
sudo systemctl start nginx
```

Verify:

```bash
curl http://localhost
```

**Hands-on flow:** `Resource Group → VM → NSG → SSH → Install Application → Verify`

<a id="vm-interview"></a>

## 17. Interview Questions

### Q1. What is Azure VM?

Azure VM is an IaaS compute service that provides a virtual server where the customer manages the OS, applications and configuration.

### Q2. Difference between VM Image and VM Size?

**Image** defines the OS/template used to create the VM.

**Size** defines the compute resources such as CPU, memory, network and supported disk capabilities.

### Q3. What is Managed Disk?

Managed Disk is Azure-managed block storage used by Azure VMs.

### Q4. Difference between OS Disk and Data Disk?

OS Disk contains the operating system. Data Disk is generally used for application and persistent data.

### Q5. What is a VM Extension?

A VM Extension is an Azure component used for post-deployment configuration, software installation or agent deployment.

### Q6. What is Custom Script Extension?

It executes scripts inside the VM for automated installation and configuration.

### Q7. How do you troubleshoot SSH failure?

`Client → IP/DNS → NSG → Route → NIC → OS Firewall → SSH Service → Authentication → Logs`

### Q8. How do you troubleshoot disk-full?

```bash
df -h
du -sh /*
```

Identify the filesystem and large files/directories, clean unnecessary data or increase storage.

### Q9. Vertical vs Horizontal Scaling?

**Vertical:** Increase VM resources.

**Horizontal:** Increase number of VM instances.

### Q10. How do you secure production VMs?

Use private access where possible, restrict NSGs, use Bastion/VPN, SSH keys or Entra-based authentication, Managed Identity, patching, encryption, monitoring and least-privilege RBAC.

<a id="vm-scenarios"></a>

## 18. Production Scenarios

### Scenario 1: Production VM is Not Reachable

**Check:** `VM Status → IP → NSG → Route → NIC → OS Firewall → Service`

**Possible Root Causes:**

- NSG blocking traffic
- Incorrect route
- Service stopped
- OS firewall blocking
- VM unhealthy

**Fix:** Correct the network or service configuration and verify connectivity.

---

### Scenario 2: Application is Slow

**Check:** `Application → CPU → Memory → Disk IOPS → Network → Dependencies → Logs`

Possible causes:

- High CPU
- Memory pressure
- Disk latency
- Network bottleneck
- Application issue
- Database dependency

---

### Scenario 3: Disk is Full

**Check:** `df -h → du → Large Files → Logs → Cleanup → Resize`

Preventive actions:

- Log rotation
- Disk monitoring
- Alerts
- Correct disk sizing

---

### Scenario 4: Same Software Required on Many VMs

Preferred:

`Standard Image / IaC → VM Provisioning → Extension/Configuration → Application Validation`

Avoid manually configuring every VM.

<a id="vm-best-practices"></a>

## 19. Best Practices

- Choose VM SKU according to workload.
- Use Managed Disks.
- Separate OS and application data where appropriate.
- Use standardized images.
- Use Availability Zones for critical workloads.
- Avoid public SSH/RDP exposure.
- Prefer Bastion, VPN or private connectivity.
- Use SSH keys for Linux.
- Use Managed Identity instead of application secrets.
- Keep operating systems patched.
- Monitor CPU, memory, disk and network.
- Configure alerts for critical resources.
- Use Infrastructure as Code for repeatable deployment.
- Use VMSS when horizontal scaling is required.
- Never store critical persistent data on temporary disks.
- Use backup for business-critical workloads.
