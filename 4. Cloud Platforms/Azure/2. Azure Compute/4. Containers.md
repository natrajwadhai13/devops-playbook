# 1. Azure Containers Overview

Azure provides multiple services for running and managing containers.

| Service                             | Purpose                                                       |
| ----------------------------------- | ------------------------------------------------------------- |
| **Azure Container Instances (ACI)** | Run containers without managing servers                       |
| **Azure Container Registry (ACR)**  | Store and manage container images                             |
| **AKS**                             | Run production Kubernetes workloads                           |
| **Container Apps**                  | Run containerized applications with managed platform features |

### Basic Flow

`Dockerfile → Build Image → Scan → ACR → Pull Image → ACI/AKS → Application`

### ACR vs ACI

| ACR                                 | ACI                                      |
| ----------------------------------- | ---------------------------------------- |
| Container image registry            | Container execution service              |
| Stores images                       | Runs containers                          |
| Similar to Docker Hub               | Serverless container execution           |
| Does not run application containers | Does not primarily act as image registry |

# 2. Azure Container Instances (ACI)

<a id="2-azure-container-instances-aci"></a>

## What is ACI?

Azure Container Instances is a serverless container service that allows you to run containers directly without managing virtual machines.

### Key Features

- No VM management
- Fast container startup
- Supports Linux and Windows containers
- Public IP support
- Environment variables
- Secrets
- CPU and memory configuration
- Restart policies
- Container groups
- Azure Virtual Network integration

### ACI Use Cases

- Development and testing
- Short-lived jobs
- Batch workloads
- CI/CD tasks
- Simple APIs
- Background processing
- Temporary workloads

### ACI is not always the best choice for

- Complex microservices
- Kubernetes workloads
- Advanced orchestration
- Large production platforms

For those workloads, **AKS** or **Azure Container Apps** may be more suitable.

---

## Create ACI

```bash
az group create \
  --name rg-containers \
  --location centralindia
```

```bash
az container create \
  --resource-group rg-containers \
  --name my-container \
  --image nginx:latest \
  --ports 80 \
  --dns-name-label my-demo-container
```

Check container:

```bash
az container show \
  --resource-group rg-containers \
  --name my-container
```

Get IP:

```bash
az container show \
  --resource-group rg-containers \
  --name my-container \
  --query ipAddress.ip
```

View logs:

```bash
az container logs \
  --resource-group rg-containers \
  --name my-container
```

# 3. Azure Container Registry (ACR)

<a id="3-azure-container-registry-acr"></a>

## What is ACR?

Azure Container Registry is Microsoft's private container registry for storing and managing container images and OCI artifacts.

### Basic Flow

`Docker Build → Docker Image → ACR → ACI/AKS`

### ACR Features

| Feature                         | Purpose                       |
| ------------------------------- | ----------------------------- |
| Private registry                | Store private images          |
| Image repositories              | Organize images               |
| Tags                            | Version images                |
| Authentication                  | Control image access          |
| Geo-replication                 | Replicate registry data       |
| Private Endpoint                | Private network access        |
| Webhooks                        | Trigger integrations          |
| Image signing/security features | Improve supply-chain security |

---

## Create ACR

```bash
az acr create \
  --resource-group rg-containers \
  --name myacrregistry123 \
  --sku Standard
```

Login:

```bash
az acr login --name myacrregistry123
```

Check registry:

```bash
az acr show \
  --name myacrregistry123 \
  --resource-group rg-containers
```

Get login server:

```bash
az acr show \
  --name myacrregistry123 \
  --query loginServer \
  --output tsv
```

Example:

```text
myacrregistry123.azurecr.io
```

# 4. Container Images

<a id="4-container-images"></a>

## What is a Container Image?

A container image is a packaged application containing:

- Application code
- Runtime
- Libraries
- Dependencies
- Configuration required to run the application

### Image Lifecycle

`Dockerfile → Build → Test → Scan → Tag → Push → Deploy`

---

## Example Dockerfile

```dockerfile
FROM nginx:alpine

COPY index.html /usr/share/nginx/html/index.html

EXPOSE 80
```

Build:

```bash
docker build -t my-app:v1 .
```

Run:

```bash
docker run -d -p 8080:80 my-app:v1
```

Test:

```bash
curl http://localhost:8080
```

---

## Tag Image for ACR

```bash
docker tag my-app:v1 myacrregistry123.azurecr.io/my-app:v1
```

Push:

```bash
docker push myacrregistry123.azurecr.io/my-app:v1
```

# 5. Container Registry Authentication

<a id="5-container-registry-authentication"></a>

ACR authentication controls who can push and pull container images.

### Common Authentication Methods

| Method                 | Use Case                             |
| ---------------------- | ------------------------------------ |
| Microsoft Entra ID     | Human and application authentication |
| Azure RBAC             | Fine-grained permissions             |
| Managed Identity       | Azure services accessing ACR         |
| Service Principal      | CI/CD automation                     |
| Admin Account          | Simple testing; avoid for production |
| Repository permissions | Control access to repositories       |

---

## ACR Admin Authentication

Enable:

```bash
az acr update \
  --name myacrregistry123 \
  --admin-enabled true
```

Get credentials:

```bash
az acr credential show \
  --name myacrregistry123
```

Login:

```bash
docker login myacrregistry123.azurecr.io
```

### Production Recommendation

Do **not** store ACR admin username/password in CI/CD pipelines.

Prefer:

`Managed Identity / Service Principal → Azure RBAC → ACR`

---

## ACR RBAC Roles

Common roles:

| Role        | Purpose                  |
| ----------- | ------------------------ |
| AcrPull     | Pull images              |
| AcrPush     | Push and pull images     |
| Owner       | Full resource management |
| Contributor | Manage registry resource |
| Reader      | Read registry resource   |

### Example

Allow an identity to pull images:

```bash
az role assignment create \
  --assignee <identity-id> \
  --role AcrPull \
  --scope /subscriptions/<subscription-id>/resourceGroups/rg-containers/providers/Microsoft.ContainerRegistry/registries/myacrregistry123
```

# 8. Image Scanning

<a id="8-image-scanning"></a>

## Why Scan Container Images?

Container images may contain:

- OS vulnerabilities
- Vulnerable packages
- Outdated dependencies
- Known CVEs
- Malware or unwanted components
- Configuration/security problems

### Secure Container Flow

`Code → Docker Build → Dependency Scan → Image Scan → ACR → Deployment`

---

## Common Scanning Tools

| Tool                              | Purpose                                         |
| --------------------------------- | ----------------------------------------------- |
| Trivy                             | Container and filesystem vulnerability scanning |
| Microsoft Defender for Cloud      | Azure security posture and workload protection  |
| Microsoft Defender for Containers | Container security                              |
| Docker Scout                      | Image analysis and vulnerabilities              |
| Snyk                              | Dependency and container security               |

---

## Trivy Example

Install/use Trivy and scan:

```bash
trivy image my-app:v1
```

Scan with severity:

```bash
trivy image \
  --severity HIGH,CRITICAL \
  my-app:v1
```

Fail pipeline on vulnerabilities:

```bash
trivy image \
  --exit-code 1 \
  --severity CRITICAL \
  my-app:v1
```

### Production Pipeline

`Build → Scan → If PASS → Push → Deploy`

If scan fails:

`Build → Scan → FAIL → Stop Pipeline`

# 10. ACI with ACR

<a id="10-aci-with-acr"></a>

ACI can run a private image stored in ACR.

### Basic Flow

`Docker Build → ACR → Authentication → ACI → Container`

---

## Using ACR Credentials

```bash
az container create \
  --resource-group rg-containers \
  --name my-app \
  --image myacrregistry123.azurecr.io/my-app:v1 \
  --registry-login-server myacrregistry123.azurecr.io \
  --registry-username <username> \
  --registry-password <password>
```

### Production Recommendation

Avoid embedding registry passwords.

Prefer managed identity where supported.

Example architecture:

`ACI Managed Identity → AcrPull → ACR → Pull Image`

# 11. CI/CD Container Flow

<a id="11-cicd-container-flow"></a>

## Production CI/CD

`Developer → Git → CI Pipeline → Build Image → Unit Test → Security Scan → Push ACR → Deploy → Smoke Test → Monitor`

### Example GitLab Flow

```yaml
stages:
  - build
  - scan
  - push
  - deploy
```

### Build

```bash
docker build -t $IMAGE_NAME:$CI_COMMIT_SHA .
```

### Scan

```bash
trivy image --exit-code 1 --severity HIGH,CRITICAL $IMAGE_NAME:$CI_COMMIT_SHA
```

### Login

```bash
az acr login --name $ACR_NAME
```

### Tag

```bash
docker tag \
  $IMAGE_NAME:$CI_COMMIT_SHA \
  $ACR_LOGIN_SERVER/my-app:$CI_COMMIT_SHA
```

### Push

```bash
docker push \
  $ACR_LOGIN_SERVER/my-app:$CI_COMMIT_SHA
```

### Deploy

```text
ACR Image → ACI / AKS → Smoke Test → Production
```

```

```

Execute command:

```bash
az container exec \
  --resource-group rg-containers \
  --name my-container \
  --exec-command "/bin/sh"
```

---

## Troubleshooting Flow

`Alert → Scope → ACI/ACR → Image → Authentication → Network → Logs → Root Cause → Fix → Verify`

### Common Problems

| Problem             | Check                | Likely Cause              |
| ------------------- | -------------------- | ------------------------- |
| Image pull failed   | ACR access           | Authentication/RBAC       |
| `unauthorized`      | ACR role             | Missing AcrPull           |
| Image not found     | Repository/tag       | Wrong image name/tag      |
| Container exits     | Logs                 | Application failure       |
| Container unhealthy | Health configuration | Application/startup issue |
| Slow startup        | Image size           | Large image               |
| Vulnerability found | Scanner              | Old package/base image    |
| Push denied         | AcrPush              | Missing permission        |
| ACR unreachable     | Network              | Firewall/private endpoint |
| ACI cannot pull     | Identity             | Missing AcrPull           |

# 15. Production Scenarios

<a id="15-production-scenarios"></a>

## Scenario 1: ACI Cannot Pull Image

**Scenario:** ACI deployment fails with image pull error.

**What will you check?**

```bash
az acr repository list --name myacrregistry123
```

Check:

- Registry URL
- Repository name
- Image tag
- ACR authentication
- AcrPull permission
- Network restrictions

**Root Cause:** ACI identity does not have permission to pull from ACR.

**Fix:** Assign `AcrPull` to the identity.

**Interview Answer:**  
"I first verify the image name and tag, then check ACR authentication, RBAC permissions, and network access. For production I prefer managed identity with AcrPull instead of storing registry passwords."

---

## Scenario 2: Image Has Critical Vulnerability

**Scenario:** Security scan reports a critical CVE.

**What will you check?**

```bash
trivy image --severity CRITICAL my-app:v1
```

Check:

- Vulnerable package
- Base image version
- Application dependency
- CVE severity
- Available fixed version

**Fix:**

`Update Base Image → Update Dependency → Rebuild → Rescan → Push → Deploy`

---

## Scenario 3: Container Starts and Immediately Stops

**Check logs:**

```bash
az container logs \
  --resource-group rg-containers \
  --name my-container
```

Check:

- Startup command
- Environment variables
- Application configuration
- Port
- Missing dependency
- Application exception

---

## Scenario 4: CI/CD Push Fails

**Error:**

```text
unauthorized
```

**Check:**

- Service principal
- Managed identity
- ACR role
- Registry login
- Token/credential expiry

Required permission for push:

```text
AcrPush
```

---

## Scenario 5: Wrong Image Deployed

**Root Cause:** Pipeline uses mutable `latest` tag.

**Better approach:**

```text
my-app:latest
```

Avoid as deployment identity.

Use:

```text
my-app:commit-a81f92c
```

or:

```text
my-app:v1.4.2
```

This makes deployments traceable and rollback easier.

# 16. Interview Questions

<a id="16-interview-questions"></a>

### Q1. What is Azure Container Instances?

ACI is a serverless container execution service that runs containers without requiring VM management.

### Q2. What is Azure Container Registry?

ACR is a private Azure registry used to store and manage container images and OCI artifacts.

### Q3. ACR vs ACI?

`ACR = Store Images`  
`ACI = Run Containers`

### Q4. What is AcrPull?

`AcrPull` allows an identity to pull images from ACR.

### Q5. What is AcrPush?

`AcrPush` allows an identity to push and pull images from ACR.

### Q6. How do you authenticate to ACR?

Using Entra ID, Azure RBAC, managed identities, service principals, or registry credentials depending on the use case.

### Q7. How would AKS pull a private image from ACR?

Give the AKS identity appropriate ACR pull permissions, commonly `AcrPull`, and ensure network connectivity.

### Q8. Why should we avoid `latest`?

It is mutable and makes deployments difficult to trace and reproduce.

### Q9. How do you scan Docker images?

Tools such as Trivy, Docker Scout, and Microsoft security services can scan container images for vulnerabilities.

### Q10. What happens when an image scan fails?

The CI/CD pipeline should stop and prevent the vulnerable image from being promoted.

### Q11. How do you troubleshoot ACR push failure?

`Check Login → Registry URL → Repository → AcrPush → Credentials/Identity → Network`

### Q12. How do you troubleshoot ACI image pull failure?

`Check Image → Tag → Registry → Authentication → AcrPull → Network → Logs`

### Q13. How do you secure ACR?

Use RBAC, managed identity, private endpoints/network controls, vulnerability scanning, least privilege, logging, and immutable/versioned image practices.

### Q14. When would you choose ACI instead of AKS?

For simple, isolated, short-lived, burstable, or development workloads where Kubernetes orchestration is unnecessary.

### Q15. Explain a production container deployment.

**Interview Answer:**

"Developer commits code to Git. CI builds the container image, runs tests and security scans, and pushes the approved image to ACR. The deployment platform pulls the immutable image from ACR using managed identity or RBAC. After deployment we run smoke tests and monitor application, container, and platform metrics."

# 17. Best Practices

<a id="17-best-practices"></a>

### Container Image

- Use minimal base images.
- Pin important versions.
- Do not include secrets in images.
- Use multi-stage Docker builds.
- Scan images before deployment.
- Remove unnecessary packages.
- Keep images small.

### ACR

- Use Azure RBAC.
- Prefer managed identity.
- Avoid ACR admin credentials in production.
- Use private endpoints when required.
- Apply least privilege.
- Enable appropriate security monitoring.
- Clean unused images/tags.
- Use meaningful image tags.

### CI/CD

`Build → Test → Scan → Push → Deploy`

- Stop pipeline on critical vulnerabilities.
- Use immutable image tags.
- Record commit SHA.
- Keep rollback image available.
- Promote the same tested image between environments.

### Production

`Git → CI/CD → Scan → ACR → Deploy → Smoke Test → Monitor`
