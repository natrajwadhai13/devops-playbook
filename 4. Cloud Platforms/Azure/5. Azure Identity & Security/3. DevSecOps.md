## 2. Microsoft Defender for Cloud

**Microsoft Defender for Cloud** is an Azure security service that helps improve the security posture of cloud resources and provides workload protection capabilities.

It helps identify:

- Security risks
- Misconfigurations
- Vulnerabilities
- Security recommendations
- Threats
- Compliance issues

### Simple Flow

```text
Azure Resources
      ↓
Defender for Cloud
      ↓
Security Assessment
      ↓
Recommendations / Alerts
      ↓
Remediation
```

### Commonly Protected Resources

- Virtual Machines
- Storage
- Databases
- Containers
- Kubernetes
- App Services
- Azure infrastructure

### Production Example

```text
VM / AKS / Storage
        ↓
Defender for Cloud
        ↓
Security Assessment
        ↓
Risk Identified
        ↓
Remediation
```

## 5. Vulnerability Scanning

**Vulnerability scanning** identifies known security weaknesses in:

- Operating systems
- Packages
- Libraries
- Dependencies
- Container images
- Applications
- Infrastructure

### Basic Flow

```text
Source Code / VM / Image
          ↓
Security Scanner
          ↓
Vulnerabilities
          ↓
Severity
          ↓
Remediation
          ↓
Rescan
```

### Common Severity Levels

| Severity | Meaning |
|---|---|
| Critical | Very high risk |
| High | High risk |
| Medium | Moderate risk |
| Low | Lower risk |

### Production Approach

Do not simply fix every finding blindly.

Prioritize based on:

- Severity
- Exploitability
- Internet exposure
- Business impact
- Available patch
- Application usage

<a id="6sast"></a>

## 6. SAST

**SAST = Static Application Security Testing**

SAST analyzes source code without executing the application.

It can identify issues such as:

- SQL injection patterns
- Hardcoded credentials
- Insecure coding patterns
- Dangerous APIs
- Security weaknesses
- Code quality issues

### SAST Flow

```text
Developer
   ↓
Git
   ↓
CI Pipeline
   ↓
SAST
   ↓
Security Findings
   ↓
Fix
   ↓
Re-scan
```

### SAST vs Runtime Testing

| Type | When | Purpose |
|---|---|---|
| SAST | Source code | Find code-level security issues |
| DAST | Running application | Find runtime/web vulnerabilities |
| Dependency Scan | Dependencies | Find vulnerable libraries |
| Container Scan | Container image | Find image/package vulnerabilities |

### Important

SAST does **not** require the application to be running.

<a id="7dependency-scanning"></a>

## 7. Dependency Scanning

Dependency scanning identifies vulnerabilities in third-party libraries used by applications.

Examples:

```text
Node.js → package.json
Java → pom.xml
Python → requirements.txt
.NET → .csproj
```

### Example

```text
Application
    ↓
Dependencies
    ↓
Dependency Scanner
    ↓
CVE Found
    ↓
Upgrade / Patch
    ↓
Re-scan
```

### Example Problem

Application uses:

```text
library-A version 1.2
```

Scanner reports:

```text
CVE-XXXX
Severity: High
Fixed Version: 1.5
```

Recommended action:

```text
Upgrade 1.2 → 1.5
```

### Production Consideration

Do not ignore dependency vulnerabilities simply because they are inside third-party libraries.

## 9. Trivy

**Trivy** is an open-source security scanner commonly used for vulnerability and security scanning.

It can scan:

- Container images
- Filesystems
- Git repositories
- Kubernetes configurations
- Infrastructure as Code
- Dependencies
- Secrets

### Basic Installation Verification

```bash
trivy --version
```

### General Syntax

```bash
trivy <target> <name>
```

Example:

```bash
trivy image nginx:latest
```

---

<a id="10trivy-container-scanning"></a>

## 10. Trivy Container Scanning

### Scan Docker Image

```bash
trivy image nginx:latest
```

### Scan Specific Image

```bash
trivy image my-app:1.0
```

### Show Only High and Critical

```bash
trivy image \
  --severity HIGH,CRITICAL \
  my-app:1.0
```

### Ignore Unfixed Vulnerabilities

```bash
trivy image \
  --ignore-unfixed \
  my-app:1.0
```

### CI/CD Example

```text
Docker Build
     ↓
Trivy Scan
     ↓
Critical/High Found?
   ↙          ↘
 Yes           No
 ↓              ↓
Fail Pipeline   Push Image
```

### Example Pipeline Logic

```bash
trivy image \
  --severity CRITICAL,HIGH \
  --exit-code 1 \
  my-app:1.0
```

If vulnerabilities matching the configured severity are found, the command can return a non-zero exit code and fail the pipeline.

<a id="11trivy-filesystem-scanning"></a>

## 11. Trivy Filesystem Scanning

Trivy can also scan the application filesystem.

```bash
trivy fs .
```

### Scan Specific Directory

```bash
trivy fs ./my-app
```

### Scan for Vulnerabilities

```bash
trivy fs \
  --scanners vuln \
  .
```

### Scan for Secrets

```bash
trivy fs \
  --scanners secret \
  .
```

### Scan for Misconfiguration

```bash
trivy fs \
  --scanners misconfig \
  .
```

### Combined

```bash
trivy fs \
  --scanners vuln,secret,misconfig \
  .
```

Example conditions:

- New bugs
- New vulnerabilities
- Code coverage
- Duplications
- Code smells
- Security ratings

### Pipeline Flow

```text

  ↓
Test
  ↓
SonarQube Scan
  ↓
Quality Gate
  ↓
Pass → Continue

```

### Example

```text

        ↓
Continue Pipeline
```

```text

        ↓

        ↓
```

### Security Gates

```text
SAST
 ↓
Dependency Scan
 ↓
SonarQube
 ↓

 ↓

```

```text
Critical Vulnerability
        ↓

        ↓
```

<a id="21devsecops-interview"></a>

## 21. Interview Questions

### Q1. What is DevSecOps?

**Answer:** DevSecOps integrates security into the software development and CI/CD lifecycle instead of performing security checks only after deployment.

### Q2. What is Defender for Cloud?

**Answer:** Defender for Cloud provides cloud security posture management, security recommendations, alerts, and workload protection capabilities for supported cloud resources.

### Q3. What is vulnerability scanning?

**Answer:** Vulnerability scanning identifies known security weaknesses in operating systems, packages, libraries, dependencies, container images, applications, or infrastructure.

### Q4. What is SAST?

**Answer:** SAST analyzes source code without executing the application to identify security vulnerabilities and insecure coding patterns.

### Q5. What is dependency scanning?

**Answer:** Dependency scanning identifies known vulnerabilities in third-party libraries used by an application.

### Q6. What is container scanning?

**Answer:** Container scanning checks container images for vulnerabilities, vulnerable packages, secrets, and other security issues depending on the scanner and configuration.

### Q7. What is Trivy?

**Answer:** Trivy is an open-source security scanner that can scan container images, filesystems, repositories, dependencies, Kubernetes configurations, and other supported targets.

### Q8. What is SonarQube?

**Answer:** SonarQube analyzes source code for bugs, vulnerabilities, code smells, security hotspots, duplication, and maintainability issues.

### Q9. Trivy vs SonarQube?

**Answer:** SonarQube primarily focuses on source code quality and security analysis, while Trivy is commonly used for vulnerability and security scanning across container images, filesystems, dependencies, secrets, and misconfigurations.

### Q10. Where should security scanning be performed in CI/CD?

**Answer:**

```text
Build
 ↓
SAST
 ↓
Dependency Scan
 ↓
SonarQube
 ↓
Container Build
 ↓
Container Scan
 ↓
Registry
 ↓
Deploy
```

### Q11. What would you do if Trivy finds a Critical vulnerability?

**Answer:** I would identify the affected package and CVE, check whether a fixed version is available, upgrade the package or base image, rebuild the image, rescan it, and deploy only after it meets the security policy.

### Q12. What is a Quality Gate?

**Answer:** A Quality Gate is a set of conditions that determines whether code meets defined quality and security standards before the pipeline can continue.

### Q13. Should every vulnerability automatically fail the pipeline?

**Answer:** Not necessarily. The pipeline policy should define thresholds based on severity, exploitability, environment, and business risk. Critical findings are commonly treated as release blockers, while exceptions should be formally reviewed and documented.

### Q14. How do you implement DevSecOps in a production pipeline?

**Answer:**

> I integrate SAST, dependency scanning, SonarQube quality gates, container scanning with tools such as Trivy, and cloud security monitoring with Defender for Cloud. Security findings are evaluated through defined gates before deployment, and production workloads continue to be monitored after deployment.

<a id="22devsecops-best-practices"></a>

## 22. Best Practices

- Shift security left.
- Scan source code early.
- Scan dependencies regularly.
- Scan container images before deployment.
- Use security gates in CI/CD.
- Block unacceptable Critical/High vulnerabilities according to policy.
- Keep base images updated.
- Keep application dependencies updated.
- Do not ignore security findings without validation.
- Document approved exceptions.
- Rescan after remediation.
- Monitor production workloads.
- Use Defender for Cloud for cloud security posture and workload protection.
- Integrate security into developer workflows.
- Store scan reports and audit results.
- Review security policies regularly.

### Production Principle

```text
Secure Code
   ↓
Secure Dependencies
   ↓
Secure Image
   ↓
Secure Infrastructure
   ↓
Secure Deployment
   ↓
Continuous Monitoring
```
