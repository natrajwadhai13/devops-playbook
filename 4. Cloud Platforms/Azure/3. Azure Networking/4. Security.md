# 1. Network Security Overview

Azure provides multiple security layers for protecting applications, infrastructure and network traffic.

### Main Components

| Service | Purpose | Layer / Scope |
|---|---|---|
| NSG | Allow/deny network traffic | Subnet/NIC |
| Azure Firewall | Centralized network traffic filtering | VNet |
| Application Gateway WAF | Protect web applications | HTTP/HTTPS |
| Azure Bastion | Secure VM administration | Management access |
| DDoS Protection | Protect public IP resources from DDoS attacks | Network |
| Private Endpoint | Private access to Azure services | Private networking |
| Defender for Cloud | Security posture and threat protection | Azure resources |

### Simple Memory

```text
NSG = Basic Network Filtering
Azure Firewall = Centralized Network Firewall
Bastion = Secure VM Access
WAF = Web Application Protection
DDoS = DDoS Attack Protection
```

Production security flow:

```text
Internet → DDoS Protection → WAF → Firewall → Application → Monitoring
```

For administrative access:

```text
Admin → Azure Portal → Bastion → Private VM
```

<a id="2-azure-firewall"></a>

# 2. Azure Firewall

Azure Firewall is a **managed, stateful network security service** used to control and inspect network traffic flowing through Azure VNets.

It provides centralized traffic filtering instead of maintaining firewall software on individual VMs.

### Key Features

- Stateful firewall
- Centralized network security
- Network rules
- Application rules
- NAT rules
- FQDN filtering
- Threat intelligence
- Logging
- High availability
- Zone redundancy
- Azure Firewall Manager / Firewall Policy integration

### Basic Architecture

```text
Internet
   ↓
Public IP
   ↓
Azure Firewall
   ↓
VNet
   ↓
Private Subnet
   ↓
Application
```

### Important

Azure Firewall is different from an NSG.

```text
NSG → Distributed subnet/NIC-level filtering
Firewall → Centralized network traffic inspection
```

<a id="3-azure-firewall-components"></a>

# 3. Azure Firewall Components

### 3.1 AzureFirewallSubnet

Azure Firewall requires a dedicated subnet:

```text
AzureFirewallSubnet
```

The subnet must be specifically used by Azure Firewall.

### 3.2 Firewall Public IP

A public IP is associated with the firewall for internet-facing traffic.

### 3.3 Firewall Policy

Firewall Policy centrally stores:

- Network rules
- Application rules
- NAT rules
- Rule collections
- Threat intelligence settings

### 3.4 Firewall Rules

Rules determine whether traffic is:

```text
Allow → Forward traffic
Deny → Block traffic
```

### 3.5 Route Table

User Defined Routes can force traffic through the firewall.

Example:

```text
Private Subnet
      ↓
Route Table
      ↓
Azure Firewall
      ↓
Internet
```

This creates centralized outbound traffic inspection.

<a id="4-azure-firewall-rule-types"></a>

# 4. Azure Firewall Rule Types

Azure Firewall commonly uses three important rule types.

## 4.1 Network Rules

Network rules control traffic based on:

- Source IP
- Destination IP
- Protocol
- Destination port

Example:

```text
Source: 10.0.1.0/24
Destination: 10.0.2.10
Protocol: TCP
Port: 443
Action: Allow
```

Typical use:

```text
Private Server → Database: TCP 1433
Private Server → API: TCP 443
```

---

## 4.2 Application Rules

Application rules control HTTP/HTTPS traffic using FQDNs.

Example:

```text
Source: 10.0.1.0/24
Protocol: HTTPS
Destination: *.microsoft.com
Action: Allow
```

Useful for controlling outbound internet access.

Example:

```text
Application Server
      ↓
Azure Firewall
      ↓
HTTPS
      ↓
approved-domain.com
```

---

## 4.3 NAT Rules

NAT rules translate incoming traffic from a firewall public IP to a private resource.

Example:

```text
Internet
   ↓
Firewall Public IP:443
   ↓
NAT Rule
   ↓
Private VM:443
```

This is useful for controlled inbound access.

---

## Rule Comparison

| Rule | Main Purpose |
|---|---|
| Network Rule | IP/Port/Protocol filtering |
| Application Rule | FQDN-based HTTP/HTTPS filtering |
| NAT Rule | Port translation / inbound publishing |

<a id="6-azure-firewall-deployment"></a>

# 6. Azure Firewall Deployment

Basic deployment flow:

```text
Resource Group
   ↓
VNet
   ↓
AzureFirewallSubnet
   ↓
Public IP
   ↓
Firewall
   ↓
Firewall Policy
   ↓
Routing
   ↓
Application
```

### Azure CLI Example

Create resource group:

```bash
az group create \
  --name rg-network-security \
  --location centralindia
```

Create VNet:

```bash
az network vnet create \
  --resource-group rg-network-security \
  --name vnet-prod \
  --address-prefix 10.0.0.0/16 \
  --subnet-name AzureFirewallSubnet \
  --subnet-prefix 10.0.1.0/24
```

Create application subnet:

```bash
az network vnet subnet create \
  --resource-group rg-network-security \
  --vnet-name vnet-prod \
  --name app-subnet \
  --address-prefix 10.0.2.0/24
```

Create public IP:

```bash
az network public-ip create \
  --resource-group rg-network-security \
  --name pip-firewall \
  --sku Standard
```

Create firewall:

```bash
az network firewall create \
  --resource-group rg-network-security \
  --name azfw-prod
```

Configure firewall IP:

```bash
az network firewall ip-config create \
  --resource-group rg-network-security \
  --firewall-name azfw-prod \
  --name fw-ipconfig \
  --public-ip-address pip-firewall \
  --vnet-name vnet-prod
```

<a id="8-azure-firewall-troubleshooting"></a>

# 8. Azure Firewall Troubleshooting

### Problem: Application cannot access internet

Check:

```text
1. NSG
2. Route Table
3. Firewall subnet
4. Firewall policy
5. Application rule
6. Network rule
7. DNS
8. Firewall logs
```

Useful commands:

```bash
az network firewall show \
  --resource-group rg-network-security \
  --name azfw-prod
```

Check routes:

```bash
az network route-table route list \
  --resource-group rg-network-security \
  --route-table-name rt-prod
```

Check NSG:

```bash
az network nsg rule list \
  --resource-group rg-network-security \
  --nsg-name nsg-app
```

### Common Root Causes

| Symptom | Possible Root Cause |
|---|---|
| Internet unavailable | Missing route |
| Traffic denied | Firewall rule |
| HTTPS unavailable | Application rule |
| DNS failure | DNS configuration |
| Private resource unreachable | Routing/NSG |
| Unexpected access | Overly broad rule |

<a id="9-azure-bastion"></a>

# 9. Azure Bastion

Azure Bastion provides secure RDP and SSH access to Azure VMs without exposing the VM's public IP.

Traditional model:

```text
Internet → Public IP → VM:22/3389
```

More secure model:

```text
Admin → Azure Portal → Bastion → Private VM
```

### Main Benefits

- No public IP required on VM
- SSH access
- RDP access
- Centralized management
- Browser-based access
- Reduced attack surface

### Memory Trick

```text
Bastion = Secure SSH/RDP Gateway
```

---

<a id="11-azure-bastion-deployment"></a>

# 11. Azure Bastion Deployment

Create Bastion subnet:

```bash
az network vnet subnet create \
  --resource-group rg-network-security \
  --vnet-name vnet-prod \
  --name AzureBastionSubnet \
  --address-prefix 10.0.3.0/26
```

Create public IP:

```bash
az network public-ip create \
  --resource-group rg-network-security \
  --name pip-bastion \
  --sku Standard
```

Create Bastion:

```bash
az network bastion create \
  --resource-group rg-network-security \
  --name bastion-prod \
  --public-ip-address pip-bastion \
  --vnet-name vnet-prod \
  --location centralindia
```

Connect through Azure CLI:

```bash
az network bastion ssh \
  --name bastion-prod \
  --resource-group rg-network-security \
  --target-resource-id <VM_RESOURCE_ID> \
  --auth-type password \
  --username azureuser
```

RDP can similarly be initiated through Bastion.

<a id="13-azure-ddos-protection"></a>

# 13. Azure DDoS Protection

DDoS means:

**Distributed Denial of Service**

An attacker sends a large volume of traffic to overwhelm a service or network resource.

Example:

```text
Attacker 1 ─┐
Attacker 2 ─┤
Attacker 3 ─┤
Attacker 4 ─┼──→ Public IP → Application
Attacker 5 ─┤
Attacker N ─┘
```

The goal is to consume:

- Bandwidth
- Network resources
- Connection capacity
- Application resources

Azure provides DDoS protection for Azure resources with public IP exposure.

---

## DDoS Protection Options

| Option | Description |
|---|---|
| DDoS IP Protection | Protection for individual public IP resources |
| DDoS Network Protection | Protection for virtual networks and supported public IP resources |

For enterprise production environments, DDoS Network Protection can provide centralized protection and additional capabilities.

### Memory Trick

```text
DDoS = Protect Availability
Firewall = Control Traffic
WAF = Protect Web Application
```

---

<a id="15-ddos-protection-vs-firewall-vs-waf"></a>

# 15. DDoS Protection vs Firewall vs WAF

| Service | Main Purpose | Example |
|---|---|---|
| DDoS Protection | Protect against volumetric/network DDoS | Massive traffic attack |
| Azure Firewall | Network traffic filtering | Allow TCP 443 |
| WAF | Web attack protection | SQL Injection/XSS |
| NSG | Basic network filtering | Allow subnet TCP 443 |
| Bastion | Secure administration | SSH/RDP to private VM |

### Easy Interview Explanation

```text
DDoS → Protect infrastructure availability
Firewall → Control network traffic
WAF → Protect HTTP/HTTPS applications
NSG → Basic subnet/NIC filtering
Bastion → Secure VM administration
```

<a id="21-best-practices"></a>

# 21. Best Practices

## Azure Firewall

- Use centralized Firewall Policy.
- Follow least-privilege rules.
- Avoid `Allow Any` rules.
- Restrict outbound internet access.
- Use FQDN filtering where appropriate.
- Enable logging.
- Monitor denied traffic.
- Use availability zones where required.
- Review firewall rules regularly.

## Bastion

- Keep production VMs private.
- Avoid public SSH/RDP.
- Use Bastion for administrative access.
- Restrict administrative identities.
- Use MFA and RBAC.
- Monitor administrative activity.

## DDoS Protection

- Protect public-facing production workloads.
- Monitor DDoS metrics.
- Combine DDoS protection with WAF.
- Use Front Door/Application Gateway where appropriate.
- Define incident response procedures.
- Test application resilience.

## Overall

```text
Public Access → Minimize
Private Access → Prefer
Firewall Rules → Least Privilege
Admin Access → Bastion
Web Protection → WAF
DDoS → DDoS Protection
Monitoring → Always Enable
```
