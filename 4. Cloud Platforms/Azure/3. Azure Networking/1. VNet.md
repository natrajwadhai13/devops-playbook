# 1. Azure Networking Overview

<a id="1-azure-networking-overview"></a>

Azure Networking provides connectivity between:

- Azure resources
- Virtual machines
- Containers
- AKS
- App Services
- On-premises networks
- Internet
- Other VNets

### Core Networking Components

| Component | Purpose |
|---|---|
| VNet | Private Azure network |
| Subnet | Logical network segment |
| CIDR | Defines IP address range |
| Private IP | Internal communication |
| Public IP | Internet-facing connectivity |
| NSG | Allow/deny network traffic |
| Route Table | Controls packet routing |
| DNS | Resolves names to IP addresses |
| VNet Peering | Connects VNets |
| VPN Gateway | Connects Azure to external networks |

### Basic Flow

`Internet → Public IP → NSG → Subnet → VM`

Internal:

`VM → Private IP → Subnet → Private IP → VM`

# 2. Virtual Network VNet

<a id="2-virtual-network-vnet"></a>

## What is Azure VNet?

Azure Virtual Network is a logically isolated network in Azure that allows Azure resources to communicate securely with each other, the internet, and on-premises networks.

Think of VNet as your **private network in Azure**.

### Example

```text
VNet: 10.0.0.0/16

├── Web Subnet      10.0.1.0/24
├── App Subnet      10.0.2.0/24
├── DB Subnet       10.0.3.0/24
└── Management      10.0.4.0/24
```

### Important

A VNet has:

- Address space
- Subnets
- Private IP addressing
- Routing
- Network security
- DNS configuration

### VNet Address Space

Example:

```text
10.0.0.0/16
```

This defines the IP range available inside the VNet.

# 3. CIDR and IP Addressing

<a id="3-cidr-and-ip-addressing"></a>

## What is CIDR?

CIDR stands for **Classless Inter-Domain Routing**.

CIDR defines an IP network and its prefix length.

Example:

```text
10.0.0.0/16
```

Where:

```text
10.0.0.0 = Network address
/16       = Prefix length
```

### Common CIDR Ranges

| CIDR | Total Addresses | Typical Use |
|---|---:|---|
| /8 | 16,777,216 | Very large network |
| /16 | 65,536 | VNet |
| /20 | 4,096 | Large subnet |
| /24 | 256 | Common subnet |
| /25 | 128 | Small subnet |
| /26 | 64 | Small subnet |
| /27 | 32 | Small subnet |
| /28 | 16 | Very small subnet |

For IPv4:

```text
Number of addresses = 2^(32 - prefix)
```

Example:

```text
10.0.1.0/24

2^(32-24)
= 2^8
= 256 addresses
```

---

## Azure Reserved IP Addresses

Azure reserves **5 IP addresses in every subnet**.

For:

```text
10.0.1.0/24
```

Azure reserves:

```text
10.0.1.0
10.0.1.1
10.0.1.2
10.0.1.3
10.0.1.255
```

Therefore:

```text
256 - 5 = 251 usable IP addresses
```

### Interview Point

Do not simply say `/24 = 256 usable IPs` in Azure.

Say:

> "A /24 subnet has 256 total IPv4 addresses, but Azure reserves 5 addresses, leaving 251 usable addresses."

---

## Private IPv4 Ranges

RFC1918 private ranges:

| Range | CIDR |
|---|---|
| 10.0.0.0 – 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 – 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 – 192.168.255.255 | 192.168.0.0/16 |

Example:

```text
VNet:       10.0.0.0/16
Web:        10.0.1.0/24
Application: 10.0.2.0/24
Database:   10.0.3.0/24
```

# 4. Public IP and Private IP

<a id="4-public-ip-and-private-ip"></a>

## Private IP

Private IP addresses are used for communication inside private networks.

Example:

```text
Web VM     → 10.0.1.10
App VM     → 10.0.2.10
DB VM      → 10.0.3.10
```

Flow:

`Web VM → Private IP → App VM → Private IP → DB`

---

## Public IP

Public IP allows Azure resources to communicate with the internet.

Example:

```text
Public IP
    ↓
Load Balancer
    ↓
VM
```

### Common Public IP Uses

- Internet-facing VM
- Azure Load Balancer
- Application Gateway
- VPN Gateway
- Bastion-related connectivity scenarios
- NAT Gateway

---

## Public vs Private IP

| Feature | Public IP | Private IP |
|---|---|---|
| Internet reachable | Yes, depending on service/config | No |
| Internal communication | Yes | Yes |
| Internet-facing application | Common | Behind public service |
| Example | `20.x.x.x` | `10.x.x.x` |
| Security exposure | Higher | Lower |

### Production Recommendation

Do not assign public IPs to every VM.

Prefer:

`Internet → Load Balancer/Application Gateway → Private VM`

# 5. Subnets

<a id="5-subnets"></a>

## What is a Subnet?

A subnet divides a VNet into smaller logical network segments.

Example:

```text
VNet 10.0.0.0/16

Web      10.0.1.0/24
App      10.0.2.0/24
Database 10.0.3.0/24
```

### Why Use Subnets?

- Network segmentation
- Security isolation
- Routing control
- Workload separation
- Different NSG policies
- Better network design

---

## Production Subnet Design

```text
VNet 10.0.0.0/16

Web Subnet       10.0.1.0/24
App Subnet       10.0.2.0/24
DB Subnet        10.0.3.0/24
Management       10.0.4.0/24
Private Endpoints 10.0.5.0/24
```

### Example Traffic

`Internet → Web → App → Database`

Direct:

`Internet → Database`

should normally be blocked.

---

## Create VNet

```bash
az network vnet create \
  --resource-group rg-network \
  --name vnet-prod \
  --address-prefix 10.0.0.0/16 \
  --subnet-name web-subnet \
  --subnet-prefix 10.0.1.0/24
```

Create another subnet:

```bash
az network vnet subnet create \
  --resource-group rg-network \
  --vnet-name vnet-prod \
  --name app-subnet \
  --address-prefixes 10.0.2.0/24
```

# 6. Network Security Group NSG

<a id="6-network-security-group-nsg"></a>

## What is NSG?

Network Security Group controls inbound and outbound network traffic using security rules.

Think:

`NSG = Network Traffic Filter`

### NSG Rule Components

| Component | Example |
|---|---|
| Priority | 100 |
| Source | Internet |
| Source Port | `*` |
| Destination | VM/Subnet |
| Destination Port | 443 |
| Protocol | TCP |
| Action | Allow |

---

## Example NSG Rules

| Priority | Direction | Source | Port | Action |
|---:|---|---|---:|---|
| 100 | Inbound | Internet | 443 | Allow |
| 110 | Inbound | Internet | 80 | Allow |
| 120 | Inbound | Admin subnet | 22 | Allow |
| 130 | Inbound | Internet | 22 | Deny |

Lower priority number = higher priority.

Example:

```text
100 Allow HTTPS
110 Allow HTTP
120 Allow SSH from Admin
130 Deny SSH from Internet
```

If priority 100 allows SSH from Internet, a later deny rule will not override it.

---

## NSG Association

NSG can be associated with:

- Subnet
- Network Interface (NIC)

### Traffic Flow

`Internet → NSG → NIC → VM`

or:

`Internet → Subnet NSG → NIC NSG → VM`

Both subnet-level and NIC-level rules can affect traffic.

---

## Create NSG

```bash
az network nsg create \
  --resource-group rg-network \
  --name nsg-web
```

Allow HTTPS:

```bash
az network nsg rule create \
  --resource-group rg-network \
  --nsg-name nsg-web \
  --name Allow-HTTPS \
  --priority 100 \
  --direction Inbound \
  --access Allow \
  --protocol Tcp \
  --destination-port-ranges 443 \
  --source-address-prefixes Internet
```

Associate with subnet:

```bash
az network vnet subnet update \
  --resource-group rg-network \
  --vnet-name vnet-prod \
  --name web-subnet \
  --network-security-group nsg-web
```

---

## NSG Troubleshooting

Check NSG:

```bash
az network nsg show \
  --resource-group rg-network \
  --name nsg-web
```

List rules:

```bash
az network nsg rule list \
  --resource-group rg-network \
  --nsg-name nsg-web \
  --output table
```

### Important Interview Point

NSG is **stateful**.

If an inbound connection is allowed, the response traffic is automatically allowed.

# 7. Route Tables

<a id="7-route-tables"></a>

## What is a Route Table?

Azure Route Table, also called **User Defined Route (UDR)**, controls how network traffic is routed.

Think:

`NSG = Can traffic flow?`

`Route Table = Where should traffic go?`

---

## Example

```text
App Subnet
    ↓
Route Table
    ↓
Firewall
    ↓
Internet
```

### Route Types

| Route | Purpose |
|---|---|
| System Route | Azure automatically creates |
| User Defined Route | Administrator-defined |
| BGP Route | Learned through VPN/ExpressRoute |

---

## Common Next Hop Types

| Next Hop | Purpose |
|---|---|
| Virtual appliance | Firewall/NVA |
| Virtual network gateway | VPN/ExpressRoute |
| Virtual network | Internal routing |
| Internet | Internet traffic |
| None | Drop traffic |

---

## Example UDR

Suppose all internet traffic must go through a firewall:

```text
Destination: 0.0.0.0/0
Next Hop: Virtual Appliance
Next Hop IP: 10.0.10.4
```

Flow:

`Application → Route Table → Firewall → Internet`

---

## Create Route Table

```bash
az network route-table create \
  --resource-group rg-network \
  --name rt-app
```

Create route:

```bash
az network route-table route create \
  --resource-group rg-network \
  --route-table-name rt-app \
  --name default-to-firewall \
  --address-prefix 0.0.0.0/0 \
  --next-hop-type VirtualAppliance \
  --next-hop-ip-address 10.0.10.4
```

Associate:

```bash
az network vnet subnet update \
  --resource-group rg-network \
  --vnet-name vnet-prod \
  --name app-subnet \
  --route-table rt-app
```

# 8. Azure DNS

<a id="8-azure-dns"></a>

## What is DNS?

DNS converts domain names into IP addresses.

```text
myapp.example.com → 20.x.x.x
```

Instead of remembering IP addresses, users access applications using DNS names.

---

## Azure DNS Services

| Service | Purpose |
|---|---|
| Azure DNS | Public DNS hosting |
| Azure Private DNS | Private DNS resolution |
| Azure DNS Private Resolver | DNS resolution between Azure/on-premises networks |

---

## Azure Public DNS

Used for public domain names.

Example:

```text
example.com
www.example.com
api.example.com
```

Typical flow:

`User → DNS → Public IP → Azure Service`

---

## Azure Private DNS

Used for private name resolution.

Example:

```text
db.internal.example.com
    ↓
10.0.3.10
```

Typical flow:

`Application → Private DNS → Private IP → Database`

### Use Cases

- Private endpoints
- Internal applications
- Private databases
- VNet-based service discovery

---

## DNS Record Types

| Record | Purpose |
|---|---|
| A | Name → IPv4 |
| AAAA | Name → IPv6 |
| CNAME | Name → Name |
| MX | Mail server |
| TXT | Verification/text |
| NS | Name servers |
| PTR | Reverse DNS |

---

## DNS Troubleshooting

Linux:

```bash
nslookup example.com
```

```bash
dig example.com
```

Windows:

```powershell
nslookup example.com
```

Check DNS configuration:

```bash
cat /etc/resolv.conf
```

### Troubleshooting Flow

`DNS Name → DNS Server → Resolution → IP → Route → NSG → Destination`

# 9. VNet and Subnet Architecture

<a id="9-vnet-and-subnet-architecture"></a>

## Three-Tier Architecture

`Internet → Public Load Balancer → Web Subnet → App Subnet → DB Subnet`

Example:

```text
VNet 10.0.0.0/16

Web       10.0.1.0/24
App       10.0.2.0/24
Database  10.0.3.0/24
```

### Security

```text
Internet → Web       Allow HTTPS
Web → App             Allow Application Port
App → Database        Allow DB Port
Internet → Database   Deny
```

### Production Flow

`User → Public IP → Load Balancer → Web → App → Database`

# 11. Networking Troubleshooting

<a id="11-networking-troubleshooting"></a>

## Standard Troubleshooting Flow

`Client → DNS → Public IP → Load Balancer → Route → NSG → NIC → VM/Application`

For private communication:

`Source → DNS → Private IP → Route → NSG → Destination`

---

## Scenario: VM Port 443 Not Accessible

### What will you check?

**1. Is VM running?**

```bash
az vm get-instance-view \
  --resource-group rg-vm \
  --name my-vm
```

**2. Is application listening?**

Linux:

```bash
ss -lntp
```

**3. Check NSG**

```bash
az network nsg rule list \
  --resource-group rg-network \
  --nsg-name nsg-web \
  --output table
```

**4. Check route**

```bash
az network route-table route list \
  --resource-group rg-network \
  --route-table-name rt-app \
  --output table
```

**5. Check firewall**

```bash
sudo iptables -L
```

or:

```bash
sudo ufw status
```

**6. Test locally**

```bash
curl -vk https://localhost
```

### Troubleshooting Flow

`DNS → IP → NSG → Route → OS Firewall → Application → Logs`

# 12. Production Scenarios

<a id="12-production-scenarios"></a>

## Scenario 1: Application Cannot Connect to Database

### What will you check?

`DNS → DB Private IP → Route → NSG → DB Port → Database Service`

Example:

```bash
nc -vz 10.0.3.10 1433
```

or:

```bash
nc -vz 10.0.3.10 3306
```

### Possible Root Causes

- Wrong DNS
- Wrong private IP
- NSG blocking traffic
- Route issue
- DB firewall
- Database service down
- Wrong port

### Interview Answer

"I first verify DNS resolution and the database private IP. Then I check routing, NSG rules, OS or database firewall, and finally confirm that the database service is listening on the expected port."

---

## Scenario 2: Internet Traffic Is Not Reaching VM

Check:

`Public IP → NSG → NIC → Route → OS Firewall → Application`

Common causes:

- No public IP
- NSG denies port
- Application not listening
- OS firewall blocks traffic
- Wrong route
- Incorrect load balancer configuration

---

## Scenario 3: Application Has Internet Access but Should Go Through Firewall

Use a UDR:

`0.0.0.0/0 → Virtual Appliance → Firewall → Internet`

Check:

- Route table association
- Next-hop IP
- Firewall rules
- NAT configuration
- Return route

---

## Scenario 4: DNS Works From One Subnet but Not Another

Check:

- VNet DNS configuration
- Private DNS zone
- VNet link
- Custom DNS server
- DNS forwarding
- NSG/firewall
- DNS resolver configuration

---

## Scenario 5: Two VNets Cannot Communicate

Check:

`VNet Address Space → Peering → Route → NSG → Firewall`

Important:

The VNet address spaces must not overlap.

Bad:

```text
VNet-A: 10.0.0.0/16
VNet-B: 10.0.0.0/16
```

Better:

```text
VNet-A: 10.0.0.0/16
VNet-B: 10.1.0.0/16
```

# 13. Interview Questions

<a id="13-interview-questions"></a>

### Q1. What is Azure VNet?

Azure VNet is a logically isolated private network in Azure used for secure communication between Azure resources, the internet, and external networks.

### Q2. What is a subnet?

A subnet is a logical division of a VNet used for network segmentation and traffic control.

### Q3. What is CIDR?

CIDR defines an IP network and its prefix length, such as `10.0.0.0/16`.

### Q4. How many IP addresses are available in `/24`?

A `/24` contains 256 total IPv4 addresses.

Azure reserves 5 addresses, so **251 are usable**.

### Q5. Private IP vs Public IP?

Private IP is primarily used for internal/private communication. Public IP provides internet-facing connectivity.

### Q6. What is NSG?

NSG is a stateful network traffic filter that allows or denies inbound and outbound traffic based on security rules.

### Q7. NSG vs Route Table?

`NSG = Whether traffic is allowed`

`Route Table = Where traffic should go`

### Q8. Can NSG be associated with a subnet?

Yes. NSG can be associated with a subnet or network interface.

### Q9. What is UDR?

User Defined Route is a custom route created by administrators to control traffic paths.

### Q10. What is the purpose of `0.0.0.0/0`?

It represents all IPv4 destinations.

Example:

```text
0.0.0.0/0 → Internet
```

or:

```text
0.0.0.0/0 → Firewall
```

depending on the route.

### Q11. What is Azure DNS?

Azure DNS provides DNS hosting and name resolution services for Azure and external domains.

### Q12. Azure DNS vs Azure Private DNS?

`Azure DNS = Public DNS`

`Azure Private DNS = Private/internal DNS`

### Q13. Why should production VMs generally avoid public IPs?

To reduce direct internet exposure. A common architecture is:

`Internet → Load Balancer/Application Gateway → Private VM`

### Q14. What happens if two VNets have overlapping address spaces?

VNet peering and many routing scenarios cannot work correctly because the address ranges are ambiguous.

### Q15. How do you troubleshoot network connectivity?

**Interview Answer:**

"I follow the traffic path from source to destination. I check DNS resolution, IP addressing, routing, NSG rules, firewall rules, connectivity to the required port, and finally the application or service listening on that port."

# 14. Best Practices

<a id="14-best-practices"></a>

### VNet

- Plan CIDR before deployment.
- Avoid overlapping address spaces.
- Reserve sufficient address space for future growth.
- Use separate subnets for different workload tiers.

### Subnets

- Separate web, application, database, and management workloads.
- Do not expose database subnets directly to the internet.
- Keep subnet sizes appropriate for future scaling.

### NSG

- Follow least privilege.
- Allow only required ports.
- Avoid `0.0.0.0/0` for sensitive management ports.
- Use specific source ranges where possible.
- Keep rule priorities organized.

### Routing

- Use UDR only when custom routing is required.
- Understand system routes before overriding them.
- Route sensitive outbound traffic through approved firewalls.

### DNS

- Use private DNS for internal services.
- Keep DNS naming consistent.
- Avoid hardcoding IP addresses in applications.
- Test DNS separately from network connectivity.

### Production Architecture

`Internet → Public Load Balancer/Application Gateway → Web Subnet → App Subnet → Private Database`
