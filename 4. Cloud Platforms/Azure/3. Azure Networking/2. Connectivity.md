# 1. Connectivity Overview

<a id="1-connectivity-overview"></a>

Azure connectivity services allow resources and networks to communicate:

- VNet to VNet
- VNet to Azure PaaS services
- Azure to on-premises
- On-premises to Azure
- Azure to branch offices
- Private application to private Azure services

### Core Connectivity Services

| Service | Main Purpose |
|---|---|
| **VNet Peering** | Connect Azure VNets |
| **Private Endpoint** | Private access to Azure PaaS services |
| **Service Endpoint** | Secure VNet access to Azure services |
| **VPN Gateway** | Encrypted connectivity over internet |
| **ExpressRoute** | Private dedicated connectivity to Azure |

### Memory Trick

```text
VNet Peering    = VNet ↔ VNet
Private Endpoint = Resource ↔ Private IP
Service Endpoint = Subnet ↔ Azure Service
VPN Gateway     = Network ↔ Azure over Internet
ExpressRoute    = Network ↔ Azure over Private Circuit
```

# 2. VNet Peering

<a id="2-vnet-peering"></a>

## What is VNet Peering?

VNet Peering connects two Azure Virtual Networks so that resources can communicate using private IP addresses.

### Basic Flow

`VNet-A → VNet Peering → VNet-B`

Example:

```text
VNet-A
10.0.0.0/16
    │
    │ Peering
    │
VNet-B
10.1.0.0/16
```

VM in VNet-A can communicate with VM in VNet-B using private IPs.

---

## Why Use VNet Peering?

- Connect application VNets
- Connect shared-services VNet
- Connect hub and spoke networks
- Private communication between workloads
- Avoid public internet communication

---

## Important Requirement

VNet address spaces should **not overlap**.

Good:

```text
VNet-A = 10.0.0.0/16
VNet-B = 10.1.0.0/16
```

Bad:

```text
VNet-A = 10.0.0.0/16
VNet-B = 10.0.0.0/16
```

---

## Types of VNet Peering

| Type | Use |
|---|---|
| Regional VNet Peering | VNets in same Azure region |
| Global VNet Peering | VNets in different Azure regions |

---

## Create Peering

Assume:

```text
vnet-prod
vnet-shared
```

Create peering from VNet-A to VNet-B:

```bash
az network vnet peering create \
  --resource-group rg-network \
  --name prod-to-shared \
  --vnet-name vnet-prod \
  --remote-vnet vnet-shared \
  --allow-vnet-access
```

Create reverse peering:

```bash
az network vnet peering create \
  --resource-group rg-network \
  --name shared-to-prod \
  --vnet-name vnet-shared \
  --remote-vnet vnet-prod \
  --allow-vnet-access
```

### Check Peering

```bash
az network vnet peering list \
  --resource-group rg-network \
  --vnet-name vnet-prod \
  --output table
```

---

## Production Hub-Spoke Architecture

```text
                    Hub VNet
                       │
          ┌────────────┼────────────┐
          │            │            │
      Spoke-Dev    Spoke-Test   Spoke-Prod
```

Hub can contain:

- Azure Firewall
- VPN Gateway
- ExpressRoute Gateway
- Bastion
- Shared services

Spokes contain:

- Applications
- AKS
- VMs
- Databases
- Workloads

# 3. Private Endpoint

<a id="3-private-endpoint"></a>

## What is a Private Endpoint?

A Private Endpoint provides private connectivity from a VNet to an Azure service using a **private IP address**.

It uses Azure Private Link.

### Basic Flow

`Application → Private IP → Private Endpoint → Azure PaaS Service`

Example:

```text
Application VM
10.0.2.10
      │
      ↓
Private Endpoint
10.0.5.10
      │
      ↓
Azure Storage / Key Vault / SQL
```

---

## Why Use Private Endpoint?

Without Private Endpoint:

```text
Application → Public Endpoint → Azure Service
```

With Private Endpoint:

```text
Application → Private IP → Azure Service
```

This allows the application to access supported Azure services privately.

---

## Common Private Endpoint Services

Examples:

- Azure Storage
- Azure Key Vault
- Azure SQL
- Azure Cosmos DB
- Azure Container Registry
- Azure Database services

---

## Important Components

| Component | Purpose |
|---|---|
| Private Endpoint | Creates private network interface |
| Private IP | Provides private address |
| Private Link | Private connectivity technology |
| Private DNS Zone | Resolves service name to private IP |

### Production Flow

`VM → Private DNS → Private Endpoint IP → Azure Service`

---

# 4. Service Endpoint

<a id="4-service-endpoint"></a>

## What is a Service Endpoint?

A Service Endpoint allows a subnet to access supported Azure services directly over the Azure backbone while the service can be restricted to selected VNets/subnets.

### Flow

`VNet Subnet → Azure Backbone → Azure Service`

Example:

```text
Application Subnet
       │
       │ Service Endpoint
       ↓
Azure Storage
```

---

## Enable Service Endpoint

Example for Storage:

```bash
az network vnet subnet update \
  --resource-group rg-network \
  --vnet-name vnet-prod \
  --name app-subnet \
  --service-endpoints Microsoft.Storage
```

Multiple services:

```bash
az network vnet subnet update \
  --resource-group rg-network \
  --vnet-name vnet-prod \
  --name app-subnet \
  --service-endpoints Microsoft.Storage Microsoft.KeyVault
```

---

## Service Endpoint Use Case

Suppose an application runs in:

```text
10.0.2.0/24
```

and needs Azure Storage.

You can configure:

`App Subnet → Service Endpoint → Storage`

Then restrict the Storage account network access to the required VNet/subnet.

---

# 5. Private Endpoint vs Service Endpoint

<a id="5-private-endpoint-vs-service-endpoint"></a>

## Important Interview Comparison

| Feature | Private Endpoint | Service Endpoint |
|---|---|---|
| Technology | Private Link | VNet Service Endpoint |
| Private IP | Yes | No private IP created for service |
| Service access | Private endpoint NIC | Azure backbone |
| DNS | Usually private DNS required | Normal service DNS |
| Public endpoint | Can be disabled | Service still has public endpoint |
| Network isolation | Stronger | Less isolated |
| Cross-region scenarios | Supported depending on service | More limited |
| On-premises private access | Yes, with appropriate connectivity | Not equivalent |
| Cost | Private Endpoint charges apply | No Private Endpoint charge |
| Recommended for sensitive workloads | Often | Depends on requirement |

### Memory Trick

```text
Private Endpoint = Private IP
Service Endpoint = Subnet Identity
```

### Interview Answer

> "A Service Endpoint extends the identity of a VNet subnet to an Azure service and secures access at the service level. A Private Endpoint creates a private IP inside the VNet and provides private connectivity to the service through Private Link."

# 6. VPN Gateway

<a id="6-vpn-gateway"></a>

## What is VPN Gateway?

Azure VPN Gateway provides encrypted connectivity between Azure VNets and external networks over the internet.

### Basic Flow

`On-Premises → Internet → VPN Tunnel → Azure VPN Gateway → VNet`

Example:

```text
On-Premises
     │
     │ Encrypted VPN
     ↓
Internet
     │
     ↓
Azure VPN Gateway
     │
     ↓
Azure VNet
```

---

## Common Use Cases

- Connect corporate datacenter to Azure
- Branch office connectivity
- Hybrid cloud
- Site-to-site VPN
- Point-to-site VPN

---

# 7. VPN Gateway Types

<a id="7-vpn-gateway-types"></a>

## Site-to-Site VPN

Connects an entire on-premises network to Azure.

```text
Corporate Network
       │
       │ S2S VPN
       ↓
Azure VPN Gateway
       │
       ↓
Azure VNet
```

### Example

```text
On-Prem: 192.168.0.0/16
Azure:   10.0.0.0/16
```

Users and servers in both networks can communicate based on routing and security rules.

---

## Point-to-Site VPN

Connects individual users/devices to Azure.

```text
Developer Laptop
       │
       │ P2S VPN
       ↓
Azure VPN Gateway
       ↓
Azure VNet
```

### Use Cases

- Administrator access
- Developer access
- Remote users
- Secure management access

---

## VPN Gateway Components

| Component | Purpose |
|---|---|
| VPN Gateway | Terminates VPN connection |
| Gateway Subnet | Dedicated subnet |
| Local Network Gateway | Represents on-premises network |
| Connection | Defines VPN connection |
| Public IP | Gateway internet connectivity |

---

## Gateway Subnet

Azure VPN Gateway requires a dedicated subnet named:

```text
GatewaySubnet
```

Example:

```text
VNet: 10.0.0.0/16

GatewaySubnet: 10.0.255.0/27
```

Do not deploy normal workloads into `GatewaySubnet`.

---

## Create Gateway Subnet

```bash
az network vnet subnet create \
  --resource-group rg-network \
  --vnet-name vnet-prod \
  --name GatewaySubnet \
  --address-prefixes 10.0.255.0/27
```

# 8. ExpressRoute

<a id="8-expressroute"></a>

## What is ExpressRoute?

Azure ExpressRoute provides private connectivity between on-premises infrastructure and Azure through a connectivity provider.

Traffic does not travel over the public internet.

### Basic Flow

`On-Premises → Connectivity Provider → ExpressRoute → Azure → VNet`

Example:

```text
Corporate Datacenter
        │
        ↓
Connectivity Provider
        │
        ↓
ExpressRoute Circuit
        │
        ↓
Azure ExpressRoute Gateway
        │
        ↓
Azure VNet
```

---

## Why ExpressRoute?

- Private connectivity
- Predictable network performance
- High reliability
- Enterprise hybrid connectivity
- Large data transfer
- Regulatory/security requirements

---

## ExpressRoute Components

| Component | Purpose |
|---|---|
| ExpressRoute Circuit | Private connectivity circuit |
| Connectivity Provider | Provides network connection |
| ExpressRoute Gateway | Connects circuit to VNet |
| BGP | Exchanges routes |
| VNet | Azure destination network |

---

## ExpressRoute vs Internet VPN

```text
VPN:
On-Prem → Internet → Encrypted Tunnel → Azure

ExpressRoute:
On-Prem → Provider → Private Circuit → Azure
```

---

# 9. VPN Gateway vs ExpressRoute

<a id="9-vpn-gateway-vs-expressroute"></a>

| Feature | VPN Gateway | ExpressRoute |
|---|---|---|
| Connectivity | Internet | Private provider connection |
| Encryption | VPN encryption | Private circuit; encryption can be added if required |
| Setup | Easier | More complex |
| Cost | Lower | Higher |
| Performance | Internet-dependent | More predictable |
| Use case | Hybrid connectivity | Enterprise connectivity |
| Deployment time | Faster | Longer |
| Provider required | No dedicated circuit provider | Yes |
| BGP | Supported | Commonly used |

### Memory Trick

`VPN = Encrypted Internet`

`ExpressRoute = Private Dedicated Connectivity`

# 12. Connectivity Troubleshooting

<a id="12-connectivity-troubleshooting"></a>

## Standard Flow

`DNS → IP → Route → Peering/VPN/Private Link → NSG → Firewall → Port → Application`

---

## Scenario: VNet Peering Not Working

### Check

```bash
az network vnet peering list \
  --resource-group rg-network \
  --vnet-name vnet-prod \
  --output table
```

Check:

- Peering state
- Both directions
- Address-space overlap
- NSG
- Route table
- Firewall
- Effective routes

### Common Root Causes

- Peering not created in both directions
- Overlapping CIDRs
- NSG blocking traffic
- Custom route overriding traffic
- Firewall blocking traffic

---

## Scenario: Private Endpoint Not Working

Check:

`Private Endpoint → Private IP → Private DNS → Route → NSG → Azure Service`

Common causes:

- Private endpoint connection not approved
- Wrong subnet
- DNS resolves to public IP
- Private DNS zone not linked
- NSG/firewall issue
- Service network restrictions

### DNS Test

```bash
nslookup <service-name>
```

The name should resolve to the expected private IP in the private-access design.

---

## Scenario: Service Endpoint Not Working

Check:

- Service endpoint enabled on correct subnet
- Azure service firewall/network rules
- VNet/subnet allowed by the service
- NSG
- Route configuration

---

## Scenario: VPN Tunnel Down

Check:

`On-Prem VPN Device → Public IP → VPN Gateway → Connection → Routes`

Check Azure connection:

```bash
az network vpn-connection show \
  --resource-group rg-network \
  --name vpn-connection
```

Common causes:

- Incorrect shared key
- Incorrect peer public IP
- Address-space mismatch
- VPN policy mismatch
- IKE/IPsec configuration mismatch
- Route/BGP issue
- On-prem firewall

---

## Scenario: ExpressRoute Connectivity Issue

Check:

`Circuit → Provider → BGP → ExpressRoute Gateway → VNet → Route → NSG`

Common causes:

- Circuit/provider issue
- BGP session down
- Incorrect route advertisement
- Gateway issue
- Route filtering
- NSG/firewall

# 13. Production Scenarios

<a id="13-production-scenarios"></a>

## Scenario 1: Connect Two Azure VNets

**Requirement:** Production VNet needs to communicate with shared-services VNet.

### Solution

Use **VNet Peering**.

```text
Prod VNet
10.0.0.0/16
      ↓
VNet Peering
      ↓
Shared VNet
10.1.0.0/16
```

### Interview Answer

"I would use VNet Peering for private communication between Azure VNets, ensuring the address spaces do not overlap and validating NSGs and routes."

---

## Scenario 2: Application Needs Private Access to Azure Key Vault

**Requirement:** Application should not access Key Vault through its public endpoint.

### Solution

Use:

`Private Endpoint + Private DNS`

Flow:

`Application → Private IP → Private Endpoint → Key Vault`

### Interview Answer

"For sensitive PaaS services such as Key Vault, I would use a Private Endpoint so the service is reachable through a private IP from the VNet."

---

## Scenario 3: Application Needs Secure Storage Access

**Requirement:** VM in a subnet needs controlled access to Azure Storage.

### Option

Use Service Endpoint when private endpoint-level isolation is not required.

```text
VM → Subnet Service Endpoint → Azure Storage
```

If the requirement is a private IP and private connectivity model, use:

```text
VM → Private Endpoint → Storage
```

---

## Scenario 4: Connect Corporate Datacenter to Azure

### Requirement

Corporate datacenter needs hybrid connectivity.

### Options

**VPN Gateway:**

`Datacenter → Internet → Encrypted VPN → Azure`

**ExpressRoute:**

`Datacenter → Provider → Private Circuit → Azure`

### Decision

Use VPN when:

- Cost is important
- Fast setup is needed
- Internet-based encrypted connectivity is acceptable

Use ExpressRoute when:

- Enterprise-grade private connectivity is required
- Predictable network performance is important
- Large-scale hybrid connectivity is needed

---

## Scenario 5: Private Endpoint DNS Resolves to Public IP

### Problem

Application is supposed to use Private Endpoint but:

```bash
nslookup <service>
```

returns the public endpoint.

### Check

- Private DNS zone
- DNS zone link to VNet
- DNS server configuration
- Private DNS record
- Custom DNS forwarding

### Root Cause

DNS is not resolving the service hostname to the Private Endpoint IP.

### Fix

Configure the appropriate Private DNS zone and VNet link.

# 14. Interview Questions

<a id="14-interview-questions"></a>

### Q1. What is VNet Peering?

VNet Peering connects Azure VNets and enables private communication using Azure's network infrastructure.

### Q2. Can you peer VNets with overlapping address spaces?

No. Overlapping address spaces create routing ambiguity and prevent normal VNet peering communication.

### Q3. What is a Private Endpoint?

A Private Endpoint creates a private network interface with a private IP in your VNet for private access to supported Azure services through Private Link.

### Q4. What is a Service Endpoint?

A Service Endpoint allows a subnet to access supported Azure services through Azure's backbone and lets the service restrict access to that subnet/VNet.

### Q5. Private Endpoint vs Service Endpoint?

**Interview Answer:**

"Private Endpoint provides a private IP inside the VNet and uses Private Link. Service Endpoint extends the subnet identity to an Azure service without creating a private IP for that service. Private Endpoint generally provides stronger private-network isolation."

### Q6. What is VPN Gateway?

VPN Gateway provides encrypted connectivity between Azure and external networks over the internet.

### Q7. Site-to-Site vs Point-to-Site VPN?

`S2S = Network-to-Network`

`P2S = Individual Client-to-Network`

### Q8. What is ExpressRoute?

ExpressRoute provides private connectivity between on-premises infrastructure and Azure through a connectivity provider.

### Q9. VPN vs ExpressRoute?

`VPN = Encrypted Internet`

`ExpressRoute = Private Provider Connectivity`

### Q10. Why do we need GatewaySubnet?

Azure VPN Gateway and ExpressRoute Gateway require a dedicated subnet named `GatewaySubnet`.

### Q11. What is Hub-Spoke architecture?

A central Hub VNet provides shared connectivity/security services while Spoke VNets contain individual workloads.

### Q12. How does Private Endpoint DNS work?

The application resolves the Azure service hostname through DNS. With appropriate Private DNS configuration, the hostname resolves to the Private Endpoint's private IP instead of the public endpoint.

### Q13. Can VNet Peering replace VPN Gateway?

Not for connecting an Azure VNet directly to an on-premises network. VNet Peering is primarily Azure VNet-to-VNet connectivity. VPN Gateway is used for VPN-based external connectivity.

### Q14. Can Private Endpoint connect an on-premises application to Azure PaaS?

Yes, when appropriate hybrid connectivity such as VPN or ExpressRoute exists and DNS/routing are correctly configured.

### Q15. How would you troubleshoot Private Endpoint connectivity?

**Interview Answer:**

"I verify the Private Endpoint state, private IP, DNS resolution, Private DNS zone and VNet link, routing, NSG/firewall rules, and finally the target Azure service's network configuration."

# 15. Best Practices

<a id="15-best-practices"></a>

## VNet Peering

- Avoid overlapping CIDRs.
- Use hub-spoke for enterprise networks.
- Control traffic using NSGs and firewalls.
- Document routing dependencies.
- Validate both peering directions.

## Private Endpoint

- Use for sensitive PaaS services.
- Configure Private DNS correctly.
- Use dedicated private endpoint subnets where appropriate.
- Disable public network access when business requirements allow.
- Use least-privilege access.

## Service Endpoint

- Enable only on required subnets.
- Restrict the Azure service to trusted VNets/subnets.
- Use Private Endpoint when a private IP/private access model is required.

## VPN Gateway

- Use strong authentication/shared keys.
- Use appropriate gateway SKUs.
- Monitor tunnel health.
- Document address spaces.
- Avoid overlapping networks.

## ExpressRoute

- Use redundant connectivity for critical production workloads.
- Monitor BGP sessions.
- Plan routing carefully.
- Use appropriate provider connectivity.
- Design for high availability.
