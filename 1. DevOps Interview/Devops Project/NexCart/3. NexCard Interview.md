# NexCart — End-to-End Azure DevOps Project

## 1. Project Overview

**NexCart** is a containerized e-commerce application designed using a microservices architecture.

The objective of the project was to build and operate an end-to-end application platform covering:

- Microservices
- Docker
- Git/GitLab

- Kubernetes
- Helm
- Azure Kubernetes Service (AKS)
- Azure Container Registry (ACR)

- Terraform
- Security scanning
- Observability
- Logging
- Monitoring
- Production troubleshooting
- Deployment and rollback

- Disaster/recovery considerations

# 9. Docker Image Strategy

I would use immutable image tags.

Instead of:

```text
latest
```

prefer:

```text
product-service:1.0.25
```

or:

```text
product-service:${CI_COMMIT_SHA}
```

For example:

```text
acr.azurecr.io/nexcart/product-service:8f91c2a
```

This gives traceability:

```text
Git Commit
    ↓
CI Pipeline
    ↓
Docker Image
    ↓
AKS Deployment
```

So during an incident we can answer:

> Which Git commit is running in production?

# 17. Why 3 Replicas?

If we have:

```text
Pod 1
Pod 2
Pod 3
```

and Pod 1 fails:

```text
Pod 1 ❌
Pod 2 ✅
Pod 3 ✅
```

Kubernetes continues serving traffic.

This provides:

- High availability
- Fault tolerance
- Better rolling deployment
- Horizontal scaling

# 26. Service Account vs Azure Identity

This is an important interview distinction.

### Kubernetes ServiceAccount

Used for:

```text
Pod → Kubernetes API
```

Example:

```yaml
serviceAccountName: nexcart-sa
```

### Azure Managed Identity

Used for:

```text
AKS Workload
      ↓
Azure Resource
```

For example:

```text
Pod
 ↓
Workload Identity
 ↓
Azure Key Vault
```

This avoids long-lived Azure client secrets.

# 27. Service Account Password/Secret Rotation

If an organization uses credentials/secrets associated with service accounts, rotation should be handled through a controlled process.

Example:

```text
Old Credential
      ↓
Create New Credential
      ↓
Update Secret Store
      ↓
Validate Application
      ↓
Deploy/Refresh Pods
      ↓
Monitor
      ↓
Disable Old Credential
```

Never:

```text
Delete old credential
        ↓
Hope application works
```

Instead use **overlapping credentials** where supported.

This gives zero/minimal downtime during rotation.

# 28. Certificate Management

A production application may use:

```text
HTTPS
TLS
Ingress
Certificate
Domain
```

A certificate will eventually expire.

Example incident:

```text
Certificate expires
       ↓
HTTPS handshake fails
       ↓
Users receive TLS error
       ↓
Application appears DOWN
```

Troubleshooting:

```bash
kubectl get certificate -A
```

```bash
kubectl describe certificate <name> -n nexcart
```

Check ingress:

```bash
kubectl get ingress -n nexcart
```

Check secret:

```bash
kubectl get secret -n nexcart
```

Check certificate externally:

```bash
openssl s_client \
  -connect example.com:443 \
  -servername example.com
```

Senior-level approach:

> Certificate expiry should not be discovered by customers. We should monitor certificate expiry and automate renewal wherever possible.

# 41. Production Incident Example

### Scenario

After deployment:

```text
Product API returns HTTP 500
```

I would not immediately restart pods.

My approach:

```text
1. Check alert
2. Identify affected service
3. Check deployment timestamp
4. Compare old/new version
5. Check application logs
6. Check pod health
7. Check database connectivity
8. Check recent configuration changes
9. Determine blast radius
10. Roll back if customer impact is high
11. Continue RCA
```

If the issue is clearly caused by the deployment:

```bash
kubectl rollout undo deployment/product-service \
  -n nexcart
```

Then:

```bash
kubectl rollout status deployment/product-service \
  -n nexcart
```

# 51. Terraform Drift

Suppose Terraform says:

```text
3 nodes
```

but someone manually changes Azure:

```text
5 nodes
```

Terraform detects the difference during:

```bash
terraform plan
```

This is called:

**Configuration drift.**

Correct approach:

```text
Detect
 ↓
Understand why manual change happened
 ↓
Decide desired state
 ↓
Update Terraform
 ↓
Apply
```

Don't blindly run `apply`.

# 60. Your Interview Introduction

When interviewer asks:

> **Tell me about your project.**

Don't start with:

> “We used Docker, Kubernetes, Azure and GitLab.”

Instead say:

NexCart is a containerized e-commerce platform that I worked on from an application deployment and DevOps perspective. The application follows a microservices architecture with services such as User, Product, Order, Payment, Notification, API Gateway and Frontend.

From the DevOps side, I worked across the complete delivery lifecycle. Developers commit code to GitLab, GitLab CI/CD validates and tests the application, performs code and security checks, builds Docker images and publishes versioned images to Azure Container Registry. The applications are then deployed to Kubernetes using Helm, with AKS used as the Azure container platform.

For configuration and security, I would keep non-sensitive configuration in Kubernetes ConfigMaps and manage sensitive information through Azure Key Vault and managed identity/workload identity rather than hardcoding credentials. The platform also includes monitoring, centralized logging and observability using Prometheus, Grafana, Loki and Alloy.

From an operations perspective, my responsibility is not limited to deployment. I also focus on troubleshooting Kubernetes workloads, application failures, networking issues, certificate renewal, secret and credential rotation, container vulnerabilities, Kubernetes upgrades, scaling, rollback and production incident management.

The important part of the architecture is that every deployment is traceable from Git commit to CI pipeline, container image, Helm release and Kubernetes workload. This gives us controlled deployments, easier troubleshooting and reliable rollback.

My role was primarily focused on the DevOps and platform side of the application. I worked on containerizing the microservices, creating the CI/CD flow, managing Docker images, Kubernetes deployments and Helm-based configuration, and designing the Azure deployment architecture.
