# ☁️ AWS Interview Questions – NexCart

## 1. NexCart AWS Project

### 1. How would you explain NexCart in an AWS DevOps interview?

> NexCart is an e-commerce microservices application consisting of Product, Order, Payment and Notification services. The services are containerized using Docker, stored in Amazon ECR and deployed to Amazon EKS using Helm. GitLab is used for source control and CI/CD. AWS services such as VPC, IAM, ALB, RDS, Secrets Manager, KMS, CloudWatch and Route 53 support the application platform.

```text
Developer
   |
GitLab
   |
GitLab CI/CD
   |
Docker Build + Security Scan
   |
Amazon ECR
   |
Helm
   |
Amazon EKS
   |
+-------------------------------+
| Product | Order | Payment     |
| Notification                 |
+-------------------------------+
   |
   +--> ALB
   +--> Database
   +--> Secrets Manager
   +--> Observability
```

---

### 2. Why did you choose AWS for NexCart?

> AWS provides mature managed services for networking, containers, databases, storage, identity, security and observability. For NexCart, EKS reduces Kubernetes control-plane management, ECR integrates with container workloads, RDS reduces database administration and IAM provides centralized authorization.

---

### 3. Why microservices for NexCart?

> Product, Order, Payment and Notification have separate responsibilities. Microservices allow independent deployment, scaling and ownership. The trade-off is increased complexity around networking, observability, security and distributed failures.

### 6. How would you design NexCart for production?

> I would use a multi-AZ VPC, private EKS nodes, ALB for application traffic, managed database services, centralized secret management, IAM least privilege, automated CI/CD, observability, autoscaling, backups and tested disaster recovery.

---

### 7. What is the difference between high availability and disaster recovery?

> HA protects against component or infrastructure failures within the normal operating environment, such as a Pod, node or AZ failure. DR addresses larger failures such as a regional outage and requires recovery of infrastructure, data and application services.

# 3. AWS Region & Availability Zones

### 8. What is an AWS Region?

> A geographical AWS location containing multiple isolated Availability Zones.

### 9. What is an Availability Zone?

> An isolated infrastructure location within a Region. Running workloads across multiple AZs reduces correlated infrastructure failure.

### 10. Why deploy EKS across multiple AZs?

> If one AZ becomes unavailable, workloads in other AZs can continue serving traffic, provided the application and dependencies are properly distributed.

### 12. Why keep EKS nodes private?

> It reduces direct Internet exposure. External traffic terminates at the load balancer while application workloads remain in private subnets.

---

### 13. What is the purpose of a public subnet?

> A public subnet contains resources that require direct routing to an Internet Gateway, such as an internet-facing load balancer or NAT Gateway infrastructure.

---

### 14. What is the purpose of a private subnet?

> Private subnets are used for workloads that should not receive direct inbound Internet traffic, such as EKS worker nodes and databases.

---

### 15. Internet Gateway vs NAT Gateway?

> Internet Gateway provides Internet connectivity for appropriately routed public resources. NAT Gateway allows private resources to initiate outbound Internet connections without exposing them to unsolicited inbound connections.

---

# 5. IAM

### 20. What is IAM?

> AWS Identity and Access Management controls authentication and authorization for AWS resources.

---

### 21. IAM User vs IAM Role?

> A user is a long-term identity, while a role provides permissions that can be assumed by trusted identities. For applications and modern human access, I prefer role-based and federated access rather than long-lived access keys.

---

### 22. What is least privilege?

> Giving an identity only the permissions required to perform its specific function.

Example:

```text
Payment Service
       |
       +--> secretsmanager:GetSecretValue
       |
       +--> kms:Decrypt
```

Not:

```text
AdministratorAccess
```

---

### 23. How do you troubleshoot AWS `AccessDenied`?

```bash
aws sts get-caller-identity
```

Then check:

```text
IAM Policy
Trust Policy
Resource Policy
Permission Boundary
SCP
Session Policy
Resource Conditions
```

---

### 24. Why should you avoid AWS access keys inside Pods?

> Long-lived credentials create security and rotation risks. EKS workload identity allows Pods to obtain temporary AWS credentials through IAM roles.

# 12. RDS / Database

### 53. Why use RDS for NexCart?

> RDS provides managed relational database capabilities, reducing the operational effort of running database infrastructure manually.

---

### 54. What is Multi-AZ RDS?

> Multi-AZ provides a highly available database architecture with standby/failover capabilities within the AWS Region.

---

### 55. Why should RDS be private?

> Database services should generally not be directly reachable from the public Internet. Access should be restricted to the application layer through private networking and security groups.

---

### 56. Application Pods increased from 5 to 20 and RDS became overloaded. Why?

> Each application Pod can create database connections. Scaling from 5 to 20 Pods can multiply database connections and query traffic. I check connection pools, DB limits, CPU, locks, slow queries and traffic before adding more Pods.

# 30. Two-Minute NexCart AWS Interview Answer

> **NexCart is an e-commerce microservices application consisting of Product, Order, Payment and Notification services. I containerized the services using Docker and use GitLab for source control and CI/CD.**
>
> **The CI/CD pipeline performs validation, testing, quality checks, security scanning and Docker image creation. Images are pushed to Amazon ECR using immutable Git-based tags.**
>
> **The application is deployed to Amazon EKS across multiple Availability Zones. Kubernetes Deployments manage the workloads, Services provide internal service discovery and Ingress integrates with an AWS Application Load Balancer. Helm manages Kubernetes deployments and environment-specific configuration.**
>
> **The AWS infrastructure layer is managed using Terraform. The architecture uses VPC, private subnets, security groups, IAM, managed database services and centralized secrets.**
>
> **For security, I use IAM least privilege and workload identity instead of static credentials. Secrets are stored in Secrets Manager and encryption is handled using KMS.**
>
> **For observability, I monitor infrastructure and application metrics, logs and traces. CloudWatch is used for AWS-level monitoring and alerting.**
>
> **From a production perspective, I focus on HA across Availability Zones, autoscaling, rollback, certificate and secret rotation, database backup, DR, security, cost optimization and Day-2 operations.**
>
> **My main principle is that a successful deployment is not enough. I need to prove that the application is secure, observable, scalable, recoverable and working from the user's business perspective.**
