## Q1. What is the difference between Continuous Integration, Continuous Delivery, and Continuous Deployment?

### Answer

| Concept | Meaning | Production Deployment |
|---|---|---|
| **Continuous Integration (CI)** | Developers frequently merge code into a shared repository, followed by automated **build and testing**. | ❌ Not necessarily |
| **Continuous Delivery** | Code is automatically **built, tested, and prepared for production**, but deployment to production requires **manual approval**. | 🟡 Manual approval |
| **Continuous Deployment** | Every change that passes the automated pipeline is **automatically deployed to production**. | ✅ Automatic |

### Easy Example

```text
Continuous Integration
Developer → Git → Build → Test
                         ↓
                       PASS


Continuous Delivery
Git → Build → Test → Staging → Manual Approval → Production


Continuous Deployment
Git → Build → Test → Staging → Automatic → Production
```

### Interview Short Answer

> **CI** focuses on integrating, building, and testing code frequently.  
> **Continuous Delivery** keeps the application production-ready, with production deployment usually requiring manual approval.  
> **Continuous Deployment** automatically deploys every validated change to production without manual intervention.

### Key Difference

**CI = Build + Test**  
**Delivery = Build + Test + Ready to Deploy + Manual Approval**  
**Deployment = Build + Test + Automatic Production Deployment**

## Q2. What are the 5 major issues you are facing in your current project?

### Answer

The major issues I commonly handle in my current project are:

1. **Application Deployment Failures**
   - CI/CD pipeline failures
   - Configuration or dependency issues
   - Deployment rollback

2. **High CPU / Memory Utilization**
   - Application or server becomes slow
   - Memory leaks or high resource-consuming processes
   - Requires monitoring and process analysis

3. **Disk Space Issues**
   - Application and system logs consuming disk space
   - Temporary files or old Docker images
   - Can cause application failures if the disk becomes full

4. **Application / API Connectivity Issues**
   - 502, 503, and 504 errors
   - Backend service unavailable
   - Nginx, firewall, DNS, or network connectivity issues

5. **SSL / Certificate Issues**
   - Certificate expiry or renewal
   - Incorrect certificate binding
   - Certificate chain or TLS configuration issues

### Interview Short Answer

> **“In my current project, the major issues I commonly handle are deployment failures, high CPU and memory utilization, disk-space issues, application connectivity problems, and SSL certificate-related issues. I troubleshoot them by checking application and system logs, resource utilization, network connectivity, configuration, and monitoring data.”**

## Q3. What activities are you involved in your current company, and what have you implemented?

### Answer

In my current project, I am involved in **application support, deployment, infrastructure automation, troubleshooting, monitoring, and security activities**.

### Key Activities

1. **Application Deployment**
   - Deploy applications across different environments.
   - Monitor deployment status and troubleshoot deployment failures.

2. **CI/CD**
   - Work with GitLab CI/CD pipelines.
   - Troubleshoot build and deployment failures.
   - Automate repetitive deployment activities.

3. **Linux / Windows Server Administration**
   - Check CPU, memory, disk and service status.
   - Perform application/server troubleshooting.
   - Handle configuration and certificate-related issues.

4. **Automation**
   - Use **Ansible/Rex** for server and application automation.
   - Automate repetitive operational tasks.

5. **Monitoring & Troubleshooting**
   - Analyze application and server logs.
   - Troubleshoot issues such as 5xx errors, connectivity problems, high resource utilization, and service failures.

### What I Have Implemented

> **“I have implemented automation for repetitive deployment and operational activities, improved CI/CD processes, worked on application/server configuration, and supported monitoring and production troubleshooting. I also worked on SSL certificate renewal/configuration and automated server-level tasks using Ansible/Rex.”**

### Short Interview Answer

> **“In my current company, I am mainly involved in application deployment, CI/CD, server administration, automation, monitoring, and production troubleshooting. I have implemented automation using Ansible/Rex, supported GitLab CI/CD pipelines, automated repetitive operational tasks, and handled application, server, and SSL-related issues.”**
